# 하루 할 일·30분 일정·날짜별 자유 기록

기능 ID: FEAT-001
버전: 0.8
상태: 구현·검수 기준
수정일: 2026-11-07

사용자는 Google 로그인 후 목표 설정 없이 현재 날짜의 고정된 다섯 줄에 할 일을 차례로 입력하고, 위·아래 위치로 중요도를 정하며 사각형 버튼에서 상태를 선택한다. 진행 전·완료·미룸·취소를 다이어리 기호로 표시한다. 잘못 변경한 상태는 원본을 유지한 채 복원할 수 있다. 왼쪽 상단에는 하루 할 일, 그 아래에는 06:00~24:00의 30분 일정표를 두고 오른쪽에는 날짜별 자유 기록을 작성한다. 입력함·완료 기록·이전 미완료는 왼쪽 아래의 접힌 이전 기록에서 확인한다. 이 흐름을 첫 구현 단위로 사용해 저장·원본 공유·접근 제어·검수 연결을 검증한다.

## 관련 요구와 범위

구글 시트의 FR-01-02~04, FR-02-02~05, FR-04-02, FR-04-05, FR-05-05, FR-07-04, FR-14-03~04, NFR-05를 참조한다. FR-02-01 및 FR-05-01 등의 전체 기능은 이 단계에서 완료했다고 처리하지 않는다. V-13은 2026-11-07의 최신 사용자 요청에 따른 날짜별 자유 기록 확장이며 전체 일기·회고 요구의 완료를 의미하지 않는다.

포함 범위는 Google 로그인·로그아웃·세션, 할 일 제목 입력, 입력함과 정리 상태, 실행 예정일 지정, 오늘 조회, 오늘 또는 선택 날짜의 할 일 목록에서 순서로 중요도 지정, 완료·완료 취소·미룸·취소·복원, 원본 재조회, 저장 실패·중복 요청·버전 충돌·권한 오류다. 2026-11-07의 최신 사용자 요청에 따라 별도 등록 폼과 유형·상중하 우선순위 선택을 없앴다. 저장된 제목도 같은 줄에서 수정하고 중요도는 행 순서로 표현한다. 현재 화면은 선택 날짜에 직접 등록하는 최대 5개 할 일과 날짜별 36칸 일정표, 일반 텍스트 자유 기록의 명시적 저장·초안 보존·실패와 충돌 복구를 포함한다. 날짜 없는 제목만의 API 생성과 기존 입력함은 호환 기능으로 유지한다. 반복·기간 일정·외부 캘린더 연동, 컬렉션·목표·회고·검색의 전체 기능, 서식 편집·이미지 첨부는 이후 별도 명세로 다룬다. 첫 기능의 마감일 편집·마감 목록은 포함하지 않는다.

## 동작

1. 목표가 없는 사용자도 제목만으로 과제를 저장할 수 있다.
2. 제목은 NFC 정규화·앞뒤 공백 제거 후 1~200 Unicode 코드 포인트를 허용하고 CR·LF·NUL은 거부한다. 세부 규칙은 공통 규칙 설계안을 따른다.
3. 현재 화면은 `1번째 할 일`부터 `5번째 할 일`까지 다섯 줄을 제공한다. 첫 빈 줄만 입력 가능하며 Enter·Tab·포커스 이동·행 안의 `할 일 저장`으로 성공 저장한 뒤 다음 빈 줄을 활성화한다. 생성은 선택 날짜를 scheduledDate로, isUnprocessed를 false로 보내 하루 할 일에 직접 수행한다. 날짜를 생략한 기존 제목만의 API 요청은 미정리·날짜 없음으로 입력함에 생성한다. 두 동작을 혼동하지 않는다.
4. 기존 입력함 항목의 `오늘로`·`이날로`는 실행일 지정과 정리 완료를 함께 요청한다. 수정 폼에서 날짜만 바꾸는 경우 정리 여부는 유지한다. 어느 경로든 새 날짜로 배정할 때 하루 5개 제한을 적용한다.
5. 현재 하루 할 일(view=day)은 완료·취소를 포함해 해당 실행일의 모든 상태를 유지한다. 완료 기록은 실제 완료 날짜에서 따로 확인한다. 기존 API의 view=scheduled는 완료 항목을 제외하는 호환 조회로 유지한다.
6. 원본 ID는 유지되며 다른 화면에서 같은 상태가 조회된다.
7. 중복 생성 요청을 재전송해도 동일한 논리 요청으로 과제가 추가 생성되지 않는다.
8. 저장 실패를 성공으로 표시하지 않으며 현재 입력을 유지한다.
9. 다른 사용자 또는 비로그인 사용자의 개인 항목 조회·수정을 거부한다.
10. 완료 취소는 원본을 미완료로 되돌리고 이전 완료 활동을 무효화하며 실행 예정일을 유지한다.
11. 최신 버전과 다른 수정은 자동 덮어쓰지 않는다. 최신 항목과 현재 편집을 비교한 뒤 사용자가 다시 반영한다.
12. 동일 키 재시도는 보관 기간 내 같은 결과를 재생한다. 기간이 지난 불확실 요청은 자동 재전송하지 않는다.
13. 현재 화면의 중요도는 위에 놓인 항목이 더 높은 순위다. 각 행의 순서 이동 핸들을 끌거나 키보드로 위치를 선택해 날짜별 순서를 저장하며 상·중·하 선택과 우선순위 배지는 모든 화면에서 제거한다. 저장된 제목은 같은 줄에서 수정하고, 날짜 변경을 위한 기존 수정 패널은 유지한다.
14. 미룸은 기호만 변경하며 실행 예정일을 자동 이동하지 않는다. 실행일을 옮기려면 날짜를 명시적으로 수정한다.
15. 취소한 항목은 삭제하지 않는다. 지정한 실행일의 하루 계획에는 취소 기호로 남고 이전 미완료에서는 제외하며, 미완료로 복원할 수 있다.
16. 날짜 없는 비완료 항목은 입력함에서 접근할 수 있어야 한다. 완료 항목을 미완료·미룸·취소로 바꾸거나 실행일을 비우면 서버가 필요한 경우 미정리로 되돌린다. 이 조건에서 정리 완료를 명시적으로 요청하면 422로 거절한다.
17. 저장된 제목의 inline 수정 또는 수정 패널 편집 중에는 다른 항목의 변경·순서 이동·신규 저장·시간대 저장·일정·자유 기록 편집과 저장·날짜 이동을 잠근다. 현재 편집의 저장과 닫기는 제공하고, 다른 저장 성공으로 편집 중인 내용을 버리지 않는다.
18. 기존 자료에서 priority·kind가 없으면 medium·task로 보충하며 제목·날짜·상태·원본 ID·버전을 보존한다. priority와 kind는 자료와 요청 재생 호환을 위한 내부 속성으로 유지하고 현재 화면에서 선택하거나 표시하지 않는다. 브라우저 체험 자료와 기존 API 요청 재생에도 같은 기본값을 적용한다.

## 우선순위·상태와 호환 계약

| 속성 | 저장값 | 화면 표기 |
|---|---|---|
| dailyOrder | 날짜별 양수 순서값, 날짜 없음은 null | 위에 놓일수록 높은 중요도, 행 순서로 표시 |
| priority | high / medium / low | 내부 호환용, 화면 표시·선택 없음 |
| status | open | □ 진행 전 |
| status | completed / deferred / canceled | ✓ 완료 / → 미룸 / × 취소 |

진행 전 표시는 기존 kind 값과 관계없이 □로 통일한다. completed에서 다른 상태로 이동하면 완료 시각을 비우고 이전 유효 완료 활동을 무효화한다. 다시 완료하면 새 완료 활동을 생성하여 현재 유효 완료는 하나만 유지한다.

기존 DB/API의 priority high·medium·low와 kind task·appointment·event는 호환을 위해 보존한다. 현재 생성·수정 화면은 이 두 필드를 전송하지 않고, 행 순서 변경도 기존 priority를 다시 쓰지 않는다. 과거 응답·요청 해시·같은 요청의 재시도를 유지한다.

우선순위·상태와 호환 API의 kind는 지정된 저장값만 허용하며 잘못된 값은 422다. 실제 변경은 버전과 관련 활동을 기록하고 동일 값은 버전·활동을 늘리지 않는다. 입력함 복귀가 서버 보충으로 발생해도 실제 변경으로 기록하되 원래 요청의 재생 해시는 바꾸지 않는다. 기존 자료의 일괄 정리 상태 보정은 이번 범위에 포함하지 않는다.

## 하루 할 일의 5개 제한 (V-12 확장)

계정·실행일별로 모든 상태의 항목을 합해 최대 5개까지 새로 배정한다. open·completed·deferred·canceled와 미정리 여부에 관계없이 같은 날짜면 한 자리로 센다. 완료·취소만으로 자리가 생기지 않으며 다른 날짜로 옮기거나 실행일을 해제해야 현재 날짜에 새 항목을 추가할 수 있다. 날짜 이동의 대상 날짜에도 같은 제한을 적용한다.

화면은 `현재 개수 / 5`와 다섯 줄을 표시한다. 비어 있는 줄은 앞줄 저장 후 차례로 열리고 5개가 저장되면 새 줄을 만들지 않는다. 기존 다섯 줄의 수정·상태·순서 변경은 계속 가능하다. 기존 자료가 5개를 넘으면 나머지는 `이전에 저장한 추가 할 일`을 펼쳐 접근하게 하며 삭제하거나 누락하지 않고 추가 배정만 막는다. API도 날짜별 잠금 안에서 개수를 확인해 생성·이동 경합이 제한을 넘지 않게 하고, 가득 찼으면 422 DAILY_TASK_LIMIT로 거부한다. 거절 시 원본·버전·활동·재생 키의 성공 상태를 남기지 않는다.

## 줄 입력·상태 메뉴·날짜별 순서 (V-12 확장)

- 별도 제목 등록 폼은 두지 않는다. 신규 행과 저장된 행 모두 같은 입력란에서 편집하며 유효한 변경은 Enter·Tab·blur·행 안의 `할 일 저장`으로 저장한다. IME 조합 중 Enter는 저장하지 않는다. 유효한 새 줄의 Enter·Tab 저장 후 다음 빈 줄로 포커스를 옮기고, Shift+Tab은 일반 역방향 탐색으로 처리한다. 빈 제목·잘못된 제목·실패한 저장은 다음 빈 줄을 열지 않으며 현재 입력과 복구 경로를 유지한다.
- 저장·되돌리기 버튼을 누르기 위한 포커스 이동은 blur 저장을 중복 실행하지 않는다. 기존 제목의 미저장 수정에는 `입력 되돌리기`를 제공한다. 제목을 수정하기 시작한 원본 버전을 보존하며, 편집 중 배경 재조회는 세션 확인만 수행하고 목록 교체를 보류한다. 편집 시작 날짜에 화면을 고정하고 일시 401에서도 초안을 보존한 채 잠그며, 실제 계정 전환에서만 이전 초안을 폐기한다. 원격 제목이나 날짜가 바뀌어도 If-Match를 몰래 최신으로 바꾸지 않는다. 충돌은 412 후 비교·선택으로 해결한다.
- 각 저장 행의 사각형 버튼은 `{제목} 상태 변경`이라는 이름을 갖고 `{제목} 상태 선택` 그룹을 연다. `완료`·`미루기`·`진행 전`·`취소`를 선택하면 각각 ✓·→·□·×로 표시한다. Escape는 메뉴를 닫고 시작 버튼으로 포커스를 돌리며 키보드·터치로 조작할 수 있다. 이전 기록의 기존 상태 선택·취소 복원은 유지한다.
- `{제목} 순서 이동` 핸들은 마우스·터치로 저장된 다른 행에 끌어 놓거나 Space로 선택 후 위아래 방향키·Home·End로 목표 위치를 지정하고 Space·Enter로 확정한다. 위·아래 화살표 버튼은 제거한다. 이동 중에는 원본 순서를 유지하고 목표 행을 표시하며 놓은 뒤 저장한다. Escape·Tab·포커스 이탈·포인터 취소·행 밖 놓기·배경 목록 변경은 저장 없이 이동을 취소한다. 저장 후 같은 항목의 핸들로 포커스를 복원한다. 드래그 동안 자정·외부 시간대 변경이 생기면 기존 날짜를 고정하며, 취소로 고정을 해제할 때 마지막 조회 날짜·시간대와 현재 표시 기준이 다르면 목록을 비우고 재조회한다. 새 날짜에 이전 행을 남기지 않는다. 제목·상태 수정과 완료 취소는 순서를 바꾸지 않는다.
- 화면 순서 변경은 `PATCH /api/tasks/{taskId}`의 단독 `{moveTo: targetTaskId}` 요청이다. 세션·Origin·CSRF·요청 키·소스 If-Match를 적용하며 다른 변경 필드와 섞거나 dailyOrder를 직접 쓰면 422다. 같은 owner·날짜의 대상이 이동 전 차지한 위치에 소스를 넣고 중간 항목들의 상대순서를 유지한다. 날짜 없는 소스와 다른 날짜 대상은 422, 없는 대상·타인 대상은 404다. 자기 자신 대상은 no-op이며 기존 단독 move up/down API도 호환 유지한다.
- 유효 이동은 날짜 잠금 아래 소스부터 대상까지 구간의 기존 dailyOrder 값들을 재사용하여 위치를 배정한다. 구간 모든 행의 version을 한 번 늘리고 같은 updatedAt과 각 order_changed 활동을 한 트랜잭션으로 반영하며 구간 밖 행은 그대로 둔다. 중간 항목의 오래된 편집도 412로 검출한다. 동일 요청 재생은 한 번만 이동하고 실패하면 전체 구간·활동·재생 상태를 함께 롤백한다.
- 신규 생성과 다른 날짜로 이동한 항목은 대상 날짜의 마지막에 붙인다. 실행일을 지우면 dailyOrder도 null이다. 날짜 간 이동은 관련 날짜를 일정한 순서로 잠그고 기존 하루 5개 제한을 유지한다. 기존 5개 초과 자료의 순서도 보존한다.

## 30분 단위 하루 일정 (V-14)

1. 왼쪽의 하루 할 일 아래 `하루 일정`은 06:00–06:30부터 23:30–24:00까지 고정된 36개 행을 제공한다. `06:00 일정`부터 `23:30 일정`까지 접근 가능한 입력 이름을 붙이고, 24:00은 끝 경계이며 별도 시작 칸이 아니다.
2. 일정은 할 일·자유 기록과 독립된 owner·날짜별 문서다. `slots`는 `{startMinute, title}` 배열이며 시작 분은 360~1410의 30분 배수, 중복 없이 최대 36개다. 서버는 시작 분 오름차순으로 정규화한다.
3. 각 제목은 할 일 제목과 같은 NFC·trim 후 1~200 Unicode 코드 포인트이며 CR·LF·NUL을 거부한다. 화면의 빈 칸은 저장 배열에서 제외하고 모든 칸을 비운 빈 배열도 유효하다. 문자열 본문을 그대로 보존하는 자유 기록과 일정 제목의 정규화 규칙을 구별한다.
4. 입력 후 `일정 저장`을 명시적으로 선택한다. 특정 칸을 지우고 저장하면 해당 칸이 삭제되고 다른 칸은 유지한다. 화면은 2시간·4칸씩 9페이지로 나누며 `일정 시간대` 선택과 이전·다음 시간대 버튼으로 전체 36칸에 접근한다. 페이지 전환은 저장 없이 같은 날짜 초안 전체를 보존하며 저장은 보이지 않는 페이지의 칸까지 포함한다. 날짜를 바꾸면 첫 시간대로 돌아간다. 저장 불확실·충돌 중에도 시간대 페이지 열람은 허용하고 쓰기만 잠근다.
5. `GET /api/schedule/{date}`와 `PUT /api/schedule/{date}`는 `{date, slots, version, updatedAt}`을 반환한다. 없는 날짜는 200·빈 배열·version 0·updatedAt null·ETag v0이며, PUT은 `{slots}`와 세션·Origin·CSRF·요청 키·If-Match를 요구한다.
6. owner·날짜별 최초 저장도 원자적으로 처리한다. 같은 정규화 배열은 no-op이고 없는 날짜의 빈 배열은 v0를 유지한다. 오래된 버전은 412이며, 같은 키·본문·If-Match의 보관 중 재시도는 최초 응답을 재생한다. 키 충돌·롤백·24시간 재시도 제한은 자유 기록과 같은 계약을 적용한다.
7. 날짜별 미저장 일정은 계정별 탭 메모리에 보존하고, 새로고침·이탈·로그아웃 전에 확인한다. 실제 계정 전환 때 폐기하며 일시 401은 잠근 채 보존한다. 이전 날짜의 지연 응답은 현재 편집을 덮지 않는다.
8. 일정 저장·불확실 pending·충돌 중에는 대상 날짜를 고정하고 날짜 이동·할 일·자유 기록·시간대 변경을 잠근다. 단순 초안이나 조회는 날짜 이동을 막지 않는다. `같은 일정 다시 저장`·`일정 저장 여부 확인`과 충돌 시 `저장된 일정 사용`·`내 일정 다시 저장`으로 복구한다.
9. 시간 표시는 선택 날짜의 로컬 시각 칸이며 UTC 예약 시각·알림·기간 이벤트를 생성하지 않는다. 반복·여러 칸을 묶는 기간·외부 캘린더 동기화는 이번 범위 밖이다.

## 날짜별 자유 기록 계약 (V-13)

1. 왼쪽 페이지의 상단에는 날짜에 직접 추가하는 하루 할 일, 아래에는 하루 일정표, 그 아래 접힌 이전 기록에는 입력함·완료 기록·이전 미완료를 배치한다. 오른쪽 페이지는 `자유 기록` 영역이며 `자유롭게 쓰는 글` 입력란과 `글 저장` 버튼을 제공한다. 620px 이하에서는 `할 일·일정`과 `자유 기록` 탭으로 표시할 책 페이지를 선택하며 두 편집기를 유지한다. 그보다 넓으면 두 페이지를 함께 표시한다.
2. 자유 기록은 과제와 독립된 owner·날짜 조합당 하나의 일반 텍스트다. 오늘의 기본 날짜는 계정 시간대를 따르며 저장된 날짜는 시간대 변경으로 이동하지 않는다. HTML·Markdown을 서식으로 실행하지 않는다.
3. 본문은 CRLF만 LF로 변환한 뒤 최대 10,000 Unicode 코드 포인트를 허용한다. NUL과 문자열 아닌 값은 거부한다. 앞뒤·연속 공백, 빈 줄, 마지막 줄바꿈을 보존하고 trim·NFC 정규화를 하지 않는다. 빈 글도 허용한다.
4. `GET /api/journal/{date}`는 해당 계정의 `{date, content, version, updatedAt}`만 반환한다. 저장된 행이 없는 날짜도 200이며 content는 빈 문자열, version은 0, updatedAt은 null이다. 조회만으로 행을 생성하지 않는다.
5. `PUT /api/journal/{date}`는 `{content}`와 세션·Origin·CSRF·요청 키·If-Match를 사용한다. 없는 날짜는 `"v0"`, 기존 날짜는 현재 버전으로 저장한다. 같은 owner·날짜의 신규 저장도 원자적으로 처리하여 경쟁 요청이 서로 덮어쓰지 않게 한다. 오래된 버전은 412, 보관 중 같은 키와 다른 본문·버전은 409다.
6. 같은 요청 키·본문·If-Match의 재시도는 24시간 보관 기간 내 최초 결과를 재생하며 글과 버전을 중복 변경하지 않는다. 재생은 현재 버전 검사보다 먼저 확인한다. 현재 본문과 같은 저장은 버전을 늘리지 않는다. 없는 날짜의 빈 글 저장은 version 0을 유지할 수 있다.
7. 자동 저장하지 않는다. 사용자가 `글 저장`을 선택하고 서버 또는 체험 저장소 확인을 마친 뒤 저장 완료를 표시한다. 성공한 글은 새로고침 후 복원한다. 저장 후 재조회한 내용이 다른 곳에서 변경됐으면 현재 글을 보존하고 충돌을 안내한다.
8. 미저장 초안은 현재 탭 메모리에서 계정·날짜별로 보관한다. 저장 전에도 날짜를 이동하고 돌아와 초안을 계속 쓸 수 있다. 이전 날짜의 지연 응답은 현재 날짜나 작성한 초안을 덮지 않는다. 계정이 바뀌면 이전 계정의 초안과 캐시를 폐기한다. 일시적인 401은 계정 전환으로 취급하지 않고 입력을 잠근 채 초안을 보존하며, 같은 계정의 세션 확인이 복구되면 계속 편집할 수 있다.
9. 어느 날짜에든 미저장 글이 있으면 새로고침·탭 이탈·로그아웃·테스트 나가기 전에 확인한다. 사용자가 이탈을 확정하면 미저장 글은 사라질 수 있다. 초안은 영구 저장이나 자동 복구를 보장하지 않는다.
10. 자유 기록을 저장 중이거나 결과가 불확실한 pending 상태이면 날짜 이동·본문 편집·할 일 변경·일정 변경·시간대 변경을 잠근다. 자정 경과나 다른 기기의 시간대 변경으로 세션의 오늘이 바뀌어도 복구를 마칠 때까지 표시·조회 날짜를 pending 요청 날짜에 고정하여 복구 대상과 본문을 일치시킨다. 단순 미저장 초안이나 글 조회 중에는 날짜 이동을 허용한다. 다른 할 일 저장·수정 중에는 자유 기록 변경을 잠근다.
11. 저장 실패 시 글과 요청을 보존하며 `같은 글 다시 저장`과 `저장 여부 확인`을 제공한다. 24시간을 지난 불확실 요청은 재전송하지 않고 저장 여부 확인으로 진행한다. 확인 결과 본문이 같으면 pending을 해제하고, 다르면 저장된 글과 내 글의 선택으로 복구한다.
12. 412 충돌에서는 내 초안을 보존하고 `저장된 글 사용` 또는 최신 버전·새 요청 키로 `내 글 다시 저장`을 선택하게 한다. 조회 실패는 빈 글로 대체하지 않고 `글 다시 불러오기`를 제공한다. 실패·충돌 상태에서 자동으로 초안을 버리거나 계속 잠긴 채 복구 경로를 숨기지 않는다.

저장 계약은 OpenAPI 0.9, 자유 기록은 `0003_daily_journal.sql`, 일정은 `0004_daily_schedule.sql`, 날짜별 순서는 `0005_task_daily_order.sql`과 연결한다. 실행 스키마는 9개 테이블과 6개 마이그레이션, 제품 계약은 11개 API 작업이다. 화면·서버·체험 경로는 같은 본문 규칙을 사용하되 실제 서버 자료와 체험 자료를 섞지 않는다.

## 날짜 선택과 화면 높이

상단 `날짜 선택` 버튼은 화면 크기와 관계없이 보인다. 같은 이름의 달력 대화상자에서 이전·다음 달을 탐색하고 날짜 또는 `오늘로 돌아가기`를 선택한다. 월 탐색만으로 현재 기록 날짜를 바꾸지 않으며 날짜 선택은 할 일·일정·자유 기록을 같은 달력 날짜로 함께 전환한다. 일별 버튼에는 년·월·일의 접근 가능한 이름을 주고 닫기·Escape 뒤에는 열었던 버튼으로 포커스를 돌린다. 기존 날짜별 초안·pending 고정·지연 응답 격리 계약을 유지한다.

1366×768, 707×978, 360×800에서 문서의 가로·세로 외부 스크롤 없이 현재 페이지의 다섯 줄·일정 4칸·저장 버튼에 접근할 수 있어야 한다. 707px에서는 양면을 유지하고 620px 이하에서만 책 페이지 탭을 사용한다. 긴 글과 이전 기록·오류 복구 등의 독립 영역은 내부 스크롤이나 대화상자로 접근하되 잘라서 숨기지 않는다. 탭 변경은 미저장 초안과 저장 복구 상태를 유지하며 저장 중에도 열람을 허용한다. 드래그 중에는 날짜·다른 변경·책 페이지 전환을 잠가 이동 대상을 보존한다.

## 상태와 공통 규칙

BR-01 원본 공유, BR-02 날짜 분리, BR-05 정리 여부와 실행 상태 분리, BR-06 완료 전환, BR-10 목표 연결 선택성을 따른다. 완료 시각과 오늘의 기준은 계정 시간대다.

## 검증과 다음 산출물

`acceptance.feature`의 시나리오를 상세 테스트로 연결한다. Gherkin 문서 자체는 자동화 실행 결과가 아니다. 계정 격리·중복 요청·완료 상태는 통합 테스트로, 입력부터 완료까지와 기호·편집 보호는 대표 E2E로 검증한다. 5줄 입력·사각형 상태 메뉴·날짜별 중요도 순서·직접 날짜 등록과 5개 제한은 V-12, 자유 기록은 V-13, 36칸 일정은 V-14로 추적한다. 기존 V-05·V-06·V-07·V-08·V-09·V-11의 저장·격리·재생·활동·충돌 규칙을 해당 흐름에 함께 적용한다.

plan.md, ux.md, data-model.md, contracts/openapi.json과 tasks.md·traceability.md에 설계·작업·검증을 연결한다. 실행 기술은 ADR-002를 따르며 구현의 시험 결과와 외부 환경 준비 상태는 docs/verification과 진행 현황에서 별도로 관리한다. 출시 날짜는 미정이다.
