# 과제 입력과 오늘 완료

기능 ID: FEAT-001
버전: 0.3
상태: 구현·검수 기준
수정일: 2026-11-07

사용자는 Google 로그인 후 목표 설정 없이 과제를 입력하고, 실행 예정일을 오늘로 지정한 뒤 오늘 화면에서 완료한다. 과제에는 우선순위와 유형을 지정하며 완료·미룸·취소를 다이어리 기호로 표시한다. 잘못 변경한 상태는 원본을 유지한 채 복원할 수 있다. 이 흐름을 첫 구현 단위로 사용해 저장·원본 공유·접근 제어·검수 연결을 검증한다.

## 관련 요구와 범위

구글 시트의 FR-01-02~04, FR-02-02~05, FR-04-02, FR-04-05, FR-05-05, FR-07-04, FR-14-03~04, NFR-05를 참조한다. FR-02-01 및 FR-05-01 등의 전체 기능은 이 단계에서 완료했다고 처리하지 않는다.

포함 범위는 Google 로그인·로그아웃·세션, 할 일 제목 입력, 입력함과 정리 상태, 실행 예정일 지정, 오늘 조회, 우선순위·유형 선택, 완료·완료 취소·미룸·취소·복원, 원본 재조회, 저장 실패·중복 요청·버전 충돌·권한 오류다. 우선순위와 다이어리 기호는 2026-11-07 사용자 요청으로 범위를 확장했다. 약속·행사는 항목의 유형이며 시간 단위 일정·컬렉션·목표·회고·검색의 전체 기능은 이후 구현한다. 첫 기능의 마감일 편집·마감 목록은 포함하지 않는다.

## 동작

1. 목표가 없는 사용자도 제목만으로 과제를 저장할 수 있다.
2. 제목은 NFC 정규화·앞뒤 공백 제거 후 1~200 Unicode 코드 포인트를 허용하고 CR·LF·NUL은 거부한다. 세부 규칙은 공통 규칙 설계안을 따른다.
3. 날짜 없는 과제는 미정리 상태로 입력함에 생성된다.
4. 오늘을 실행 예정일로 지정하면 오늘 과제 목록에 같은 원본이 표시된다. 이 조작이 입력함 정리 완료를 자동 의미하지 않는다.
5. 완료 처리 후 오늘 활성 목록에서는 제외하고 완료 기록에서 확인한다.
6. 원본 ID는 유지되며 다른 화면에서 같은 상태가 조회된다.
7. 중복 생성 요청을 재전송해도 동일한 논리 요청으로 과제가 추가 생성되지 않는다.
8. 저장 실패를 성공으로 표시하지 않으며 현재 입력을 유지한다.
9. 다른 사용자 또는 비로그인 사용자의 개인 항목 조회·수정을 거부한다.
10. 완료 취소는 원본을 미완료로 되돌리고 이전 완료 활동을 무효화하며 실행 예정일을 유지한다.
11. 최신 버전과 다른 수정은 자동 덮어쓰지 않는다. 최신 항목과 현재 편집을 비교한 뒤 사용자가 다시 반영한다.
12. 동일 키 재시도는 보관 기간 내 같은 결과를 재생한다. 기간이 지난 불확실 요청은 자동 재전송하지 않는다.
13. 빠른 입력과 수정에서 우선순위·유형을 선택하고 목록에서 우선순위·상태를 변경할 수 있다. 새 항목의 기본값은 우선순위 중·유형 할 일이다.
14. 미룸은 기호만 변경하며 실행 예정일을 자동 이동하지 않는다. 실행일을 옮기려면 날짜를 명시적으로 수정한다.
15. 취소한 항목은 삭제하지 않는다. 지정한 실행일의 하루 계획에는 취소 기호로 남고 이전 미완료에서는 제외하며, 미완료로 복원할 수 있다.
16. 날짜 없는 비완료 항목은 입력함에서 접근할 수 있어야 한다. 완료 항목을 미완료·미룸·취소로 바꾸거나 실행일을 비우면 서버가 필요한 경우 미정리로 되돌린다. 이 조건에서 정리 완료를 명시적으로 요청하면 422로 거절한다.
17. 항목 수정 중에는 다른 항목의 변경·빠른 입력 저장·시간대 저장·날짜 이동을 잠근다. 현재 편집의 저장과 닫기는 제공하고, 다른 저장 성공으로 편집 중인 내용을 버리지 않는다.
18. 기존 자료에서 우선순위·유형이 없으면 중·할 일로 보충하며 제목·날짜·상태·원본 ID·버전을 보존한다. 브라우저 체험 자료와 기존 API 요청 재생에도 같은 기본값을 적용한다.

## 우선순위·유형·상태 계약

| 속성 | 저장값 | 화면 표기 |
|---|---|---|
| priority | high / medium / low | 상 / 중 / 하 |
| kind | task / appointment / event | □ 할 일 / △ 약속 / ○ 행사 |
| status | open | 현재 유형의 기호와 미완료 |
| status | completed / deferred / canceled | ✓ 완료 / → 미룸 / × 취소 |

유형과 실행 상태는 별도 속성이다. 완료·미룸·취소에서도 원래 유형을 보존하고 미완료 복원 시 해당 유형의 기호를 다시 표시한다. completed에서 다른 상태로 이동하면 완료 시각을 비우고 이전 유효 완료 활동을 무효화한다. 다시 완료하면 새 완료 활동을 생성하여 현재 유효 완료는 하나만 유지한다.

우선순위·유형·상태는 지정된 저장값만 허용하며 잘못된 값은 422다. 실제 변경은 버전과 관련 활동을 기록하고 동일 값은 버전·활동을 늘리지 않는다. 입력함 복귀가 서버 보충으로 발생해도 실제 변경으로 기록하되 원래 요청의 재생 해시는 바꾸지 않는다. 기존 자료의 일괄 정리 상태 보정은 이번 범위에 포함하지 않는다.

## 상태와 공통 규칙

BR-01 원본 공유, BR-02 날짜 분리, BR-05 정리 여부와 실행 상태 분리, BR-06 완료 전환, BR-10 목표 연결 선택성을 따른다. 완료 시각과 오늘의 기준은 계정 시간대다.

## 검증과 다음 산출물

`acceptance.feature`의 시나리오를 상세 테스트로 연결한다. Gherkin 문서 자체는 자동화 실행 결과가 아니다. 계정 격리·중복 요청·완료 상태는 통합 테스트로, 입력부터 완료까지와 기호·편집 보호는 대표 E2E로 검증한다. 이번 확장 검수는 V-12로 추적하며 기존 V-05·V-09·V-11의 저장·활동·충돌 규칙을 함께 적용한다.

plan.md, ux.md, data-model.md, contracts/openapi.json과 tasks.md·traceability.md에 설계·작업·검증을 연결한다. 실행 기술은 ADR-002를 따르며 구현의 시험 결과와 외부 환경 준비 상태는 docs/verification과 진행 현황에서 별도로 관리한다. 출시 날짜는 미정이다.
