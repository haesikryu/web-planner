# 첫 기능 구현 설계

상태: 구현·검수 설계 · 2026-11-07

## 구조

브라우저 → 동일 출처의 웹·API 서버 → 관계형 저장소의 단일 서비스로 시작한다. 인증·과제·날짜·조회·활동·자유 기록·일정 모듈을 내부 경계로 구분한다. Google 인증은 서버 측 검증 라이브러리 어댑터로 감싼다. 첫 기능에 마이크로서비스나 별도 메시지 브로커를 도입하지 않는다.

실행 기술은 ADR-002에 따라 Next.js·React·TypeScript, Better Auth, PostgreSQL·Drizzle로 선정했다. 기본 앱·타입·린트·단위·브라우저 검증을 구성했다. 선택 기준은 계약 검증, 트랜잭션·유일 제약, Google 지원, 시간대 처리, 테스트 격리, 배포·복원 용이성이다. 운영 호스팅은 미선정이며 유료 서비스나 운영 환경을 생성하지 않는다.

## 계약

기계 판독 계약은 `contracts/openapi.json`이다. OpenAPI 3.1.1을 호환 기준으로 사용하며 최신 버전이라는 주장은 하지 않는다.

| API | 역할 |
|---|---|
| GET /api/session | 로그인 사용자·계정 시간대·서버 날짜·CSRF 토큰 확인 |
| POST /api/logout | 세션 종료 |
| PATCH /api/settings | 계정 시간대 명시적 변경 |
| GET /api/tasks | day 전체 상태·기존 scheduled·입력함·이전 미완료·완료일 조회 |
| POST /api/tasks | 선택 날짜 직접 생성·날짜별 5개 제한, 날짜 생략의 기존 입력함 계약 유지 |
| GET /api/tasks/{taskId} | 원본과 ETag 조회 |
| PATCH /api/tasks/{taskId} | 제목·실행일·정리 여부·상태·완료 취소, 단독 moveTo로 날짜별 구간 순서 이동, 기존 move 호환, priority·kind 호환 |
| GET /api/journal/{date} | 소유자의 날짜별 자유글, 없으면 빈 글과 ETag v0 |
| PUT /api/journal/{date} | 버전·요청 키를 검증해 날짜별 자유글 저장 |
| GET /api/schedule/{date} | 소유자의 날짜별 일정, 없으면 빈 slots와 ETag v0 |
| PUT /api/schedule/{date} | 36칸의 일정 배열을 버전·요청 키와 함께 원자적으로 저장 |

Google 시작·콜백 경로는 인증 라이브러리가 담당하며 제품 데이터 API 계약과 분리한다. 쓰기 API의 JSON Content-Type, Origin·CSRF 검사, 소유권 검사, 필수 헤더, 요청 키 재생 규칙을 구현한다. 사용자·공급자 인증정보를 요청 본문으로 대신 받아 로그인시키지 않는다.

오류는 code·message·requestId를 갖고 개인정보 없는 설명을 제공한다. 401 미인증, 403 CSRF/Origin 오류, 404 없음/타인 항목, 409 키 충돌·처리중, 412 버전 충돌, 422 입력 오류·DAILY_TASK_LIMIT, 428 If-Match 누락, 429 요청 제한, 500 내부 오류를 사용한다. 500에서 원문 예외·SQL·토큰을 반환하지 않는다. 요청 제한은 사용자·IP를 함께 고려하며 실제 수치는 기술·운영 검토에서 정한다.

현재 화면은 고정된 다섯 줄의 첫 빈 줄부터 차례로 입력한다. Enter·Tab·blur·행 저장은 POST에 scheduledDate와 isUnprocessed=false를 전송하고 view=day로 완료·취소를 포함한 날짜별 목록을 dailyOrder·createdAt·id 순으로 읽는다. IME 조합 중 Enter는 제출하지 않는다. 저장된 제목도 같은 줄에서 수정하며 원본 버전 스냅샷으로 If-Match를 보낸다. 유형·상중하 우선순위 선택과 위아래 버튼은 없고 드래그 핸들의 마우스·터치·키보드 조작으로 순서를 지정한다. 위에 놓을수록 중요하다. 생성·다른 날짜로 이동할 때 owner·날짜 잠금으로 5개 한도를 검증한다. 날짜 없는 API 생성과 기존 view=scheduled는 호환을 위해 유지한다. 목록의 미정리 필터는 상태와 독립적이다. today 대신 서버가 반환한 달력 날짜와 explicit 필터를 사용한다. 완료 기록은 완료일 필터로, 날짜 배정 과제는 실행일 필터로 구분한다. 마감 조회 API 확장은 다음 과제 상세 기능에서 추가하며 첫 화면 마감 영역은 해당 확장 전까지 숨긴다.

날짜별 순서는 nullable 양수 dailyOrder로 저장한다. 신규 생성과 날짜 이동은 대상 날짜의 마지막에 붙이며 날짜를 해제하면 null로 만든다. 단독 PATCH moveTo는 같은 owner·날짜 대상의 원래 인덱스로 소스를 삽입하고 중간 행을 상대순서대로 민다. 기존 구간의 순서값을 재사용하고 영향 구간 모든 버전 증가·order_changed 활동·재생 응답을 원자적으로 저장한다. 자기 자신은 no-op이며 다른 필드와 조합하거나 직접 dailyOrder를 쓰는 요청은 거부한다. 단독 move up/down은 기존 API 호환용으로 남긴다. 날짜 간 쓰기는 정렬된 날짜 잠금 후 원본 행을 다시 확인해 경합과 교착을 제한한다.

브라우저는 포인터 캡처 기반 드래그와 Space·방향키·Home/End·Space/Enter 키보드 조작을 제공한다. 이동 중 목표만 표시하고 확정 때 한 번 요청한다. Escape·포인터 취소·범위 밖 놓기·목록 변경은 쓰기 없이 취소한다. 날짜 선택은 항상 보이는 버튼과 native dialog의 달력으로 제공하며, 기록 날짜 전환·초안과 pending 계약은 기존대로 유지한다.

화면은 뷰포트 높이를 기준으로 배치한다. 일정은 4칸씩 9페이지로 표시하며 페이지 이동과 무관하게 날짜별 slots 초안 전체를 저장한다. 620px 이하의 책 페이지 탭은 두 편집기를 유지한 채 표시만 바꾸고, 저장 중 열람은 허용하되 드래그 중 전환은 막는다. 외부 문서 스크롤과 콘텐츠 잘림을 각각 검증한다.

inline 편집 동안 배경 새로고침은 세션 확인만 수행하고 할 일 페이지 교체를 보류한다. 편집을 시작한 실행일을 화면에 고정하고 일시 401에서도 원본과 초안을 보존한 채 잠근다. 원격 제목이 내 초안과 같아지거나 다른 날짜로 옮겨져도 원래 버전의 저장 요청으로 충돌을 확인한다. 성공 응답 이후 재조회로 영향 구간의 버전과 화면 순서를 동기화하며, 상태·순서 조작의 포커스는 항목 ID로 복원한다.

## 검증

- 단위: 제목 정규화·길이, 날짜 경계·DST, 상태 판정, 자유글의 공백·줄바꿈·10,000자 규칙, 일정 36칸 경계·중복·정렬·제목 규칙, 날짜별 순서와 move 입력 규칙.
- 통합: 계정 격리, 트랜잭션, 유일 제약, 키 재생, 버전 충돌, 완료 취소, 날짜별 자유글·일정 동시 첫 저장, 5개 한도의 생성·날짜 이동 경합, 장거리 순서 이동·구간 버전·활동의 원자성·동일 키 재생·원격 변경 충돌.
- 계약: 입력·응답·오류·헤더와 OpenAPI 일치.
- E2E: 다섯 줄의 순차 입력·IME·Enter/Tab/blur/행 저장 → inline 제목 편집·상태 메뉴·키보드/마우스/터치 드래그·취소·새로고침 → 완료 취소·5개 제한과 이동 후 자리 확보, 일정 첫/마지막 칸·날짜별 저장, 자유글·일정 초안 이동·실패·충돌·세션 복구, 날짜 선택 동기화·일정9페이지·세 뷰포트 외부 스크롤/잘림 검사.
- 운영: 저장 실패율·응답 지연·충돌 횟수만 집계. 본문·검색어·토큰 제외.

명세 구조 검사는 문서·JSON 연결을 확인한다. 제품 API는 OpenAPI 문서 버전 0.9.0의 11개 작업 스키마로 응답 계약을 검증하며 PostgreSQL 18에서 동시 요청·롤백·복원을 시험한다. PC·모바일 제품 E2E와 자동 접근성 검사를 추가했다. 실제 Google·운영 부하 검증과는 구분한다. 최신 결과는 docs/verification/planner-core.md와 traceability.md를 따른다. 실제 CI는 `.github/workflows/verify.yml`이다.

실행 DB는 9개 테이블이며 0000~0005의 6개 순차 마이그레이션을 적용한다. `0005_task_daily_order.sql`은 기존 날짜별 생성 순서를 backfill하며 원본·버전과 5개 초과 기록을 보존한다. `schedule_entries`와 `journal_entries`는 과제 활동과 독립되고, 동일 계정·날짜 쓰기 잠금은 목적별 scope를 분리한다. 36칸은 로컬 시각의 계획표이며 반복·기간 이벤트·외부 캘린더 연동은 추가하지 않는다.

## 배포 진입 조건

기술 선정, Google OAuth 환경 설정, D-01 가입 범위 결정, 마이그레이션·백업 복원, 핵심 수용 시나리오 검증이 필요하다. 공개 저장소 생성이나 이 설계 초안 작성으로 배포 승인을 간주하지 않는다.
