# 첫 기능 구현 설계

상태: 구현·검수 설계 · 2026-11-07

## 구조

브라우저 → 동일 출처의 웹·API 서버 → 관계형 저장소의 단일 서비스로 시작한다. 인증·과제·날짜·조회·활동·자유 기록·일정 모듈을 내부 경계로 구분한다. Google 인증은 서버 측 검증 라이브러리 어댑터로 감싼다. 첫 기능에 마이크로서비스나 별도 메시지 브로커를 도입하지 않는다.

실행 기술은 ADR-002에 따라 Next.js·React·TypeScript, Better Auth, PostgreSQL·Drizzle로 선정했다. 기본 앱·타입·린트·단위·브라우저 검증을 구성했다. 선택 기준은 계약 검증, 트랜잭션·유일 제약, Google 지원, 시간대 처리, 테스트 격리, 배포·복원 용이성이다. 운영 호스팅은 미선정이며 유료 서비스나 운영 환경을 생성하지 않는다.

## 계약

기계 판독 계약은 `contracts/openapi.json`이다. OpenAPI 3.1.1을 호환 기준으로 사용하며 최신 버전이라는 주장은 하지 않는다.

| API | 역할 |
|---|---|
| GET /api/session | 로그인 사용자·계정 시간대·서버 날짜·CSRF 토큰 확인 |
| POST /api/logout | 세션 종료 |
| PATCH /api/settings | 계정 시간대 명시적 변경 |
| GET /api/tasks | day 전체 상태·기존 scheduled·입력함·이전 미완료·완료일 조회 |
| POST /api/tasks | 선택 날짜 직접 생성·날짜별 5개 제한, 날짜 생략의 기존 입력함 계약 유지 |
| GET /api/tasks/{taskId} | 원본과 ETag 조회 |
| PATCH /api/tasks/{taskId} | 실행일·정리 여부·우선순위·상태·완료 취소 |
| GET /api/journal/{date} | 소유자의 날짜별 자유글, 없으면 빈 글과 ETag v0 |
| PUT /api/journal/{date} | 버전·요청 키를 검증해 날짜별 자유글 저장 |
| GET /api/schedule/{date} | 소유자의 날짜별 일정, 없으면 빈 slots와 ETag v0 |
| PUT /api/schedule/{date} | 36칸의 일정 배열을 버전·요청 키와 함께 원자적으로 저장 |

Google 시작·콜백 경로는 인증 라이브러리가 담당하며 제품 데이터 API 계약과 분리한다. 쓰기 API의 JSON Content-Type, Origin·CSRF 검사, 소유권 검사, 필수 헤더, 요청 키 재생 규칙을 구현한다. 사용자·공급자 인증정보를 요청 본문으로 대신 받아 로그인시키지 않는다.

오류는 code·message·requestId를 갖고 개인정보 없는 설명을 제공한다. 401 미인증, 403 CSRF/Origin 오류, 404 없음/타인 항목, 409 키 충돌·처리중, 412 버전 충돌, 422 입력 오류·DAILY_TASK_LIMIT, 428 If-Match 누락, 429 요청 제한, 500 내부 오류를 사용한다. 500에서 원문 예외·SQL·토큰을 반환하지 않는다. 요청 제한은 사용자·IP를 함께 고려하며 실제 수치는 기술·운영 검토에서 정한다.

현재 화면은 POST에 scheduledDate와 isUnprocessed=false를 전송하고 view=day로 완료·취소를 포함한 날짜별 목록을 읽는다. 생성·다른 날짜로 이동할 때 owner·날짜 잠금으로 5개 한도를 검증한다. 날짜 없는 API 생성과 기존 view=scheduled는 호환을 위해 유지한다. 목록의 미정리 필터는 상태와 독립적이다. today 대신 서버가 반환한 달력 날짜와 explicit 필터를 사용한다. 완료 기록은 완료일 필터로, 날짜 배정 과제는 실행일 필터로 구분한다. 마감 조회 API 확장은 다음 과제 상세 기능에서 추가하며 첫 화면 마감 영역은 해당 확장 전까지 숨긴다.

## 검증

- 단위: 제목 정규화·길이, 날짜 경계·DST, 상태 판정, 자유글의 공백·줄바꿈·10,000자 규칙, 일정 36칸 경계·중복·정렬·제목 규칙.
- 통합: 계정 격리, 트랜잭션, 유일 제약, 키 재생, 버전 충돌, 완료 취소, 날짜별 자유글·일정 동시 첫 저장, 5개 한도의 생성·날짜 이동 경합.
- 계약: 입력·응답·오류·헤더와 OpenAPI 일치.
- E2E: 선택 날짜 직접 입력 → 우선순위·상태 변경 → 완료 취소·5개 제한과 이동 후 자리 확보, 일정 첫/마지막 칸·날짜별 저장, 자유글·일정 초안 이동·실패·충돌·세션 복구.
- 운영: 저장 실패율·응답 지연·충돌 횟수만 집계. 본문·검색어·토큰 제외.

명세 구조 검사는 문서·JSON 연결을 확인한다. 제품 API는 OpenAPI 문서 버전 0.7.0 의 11개 작업 스키마로 응답 계약을 검증하며 PostgreSQL 18에서 동시 요청·롤백·복원을 시험한다. PC·모바일 제품 E2E와 자동 접근성 검사를 추가했다. 실제 Google·운영 부하 검증과는 구분한다. 최신 결과는 docs/verification/planner-core.md와 traceability.md를 따른다. 실제 CI는 `.github/workflows/verify.yml`이다.

실행 DB는 9개 테이블이며 0000~0004의 5개 순차 마이그레이션을 적용한다. `schedule_entries`와 `journal_entries`는 과제 활동과 독립되고, 동일 계정·날짜 쓰기 잠금은 목적별 scope를 분리한다. 36칸은 로컬 시각의 계획표이며 반복·기간 이벤트·외부 캘린더 연동은 추가하지 않는다.

## 배포 진입 조건

기술 선정, Google OAuth 환경 설정, D-01 가입 범위 결정, 마이그레이션·백업 복원, 핵심 수용 시나리오 검증이 필요하다. 공개 저장소 생성이나 이 설계 초안 작성으로 배포 승인을 간주하지 않는다.
