# 하루 할 일·일정·자유 기록 화면 흐름

상태: 화면 구현·검수 기준

## 날짜별 다이어리 화면 (2026-11-07)

PC와 가로 태블릿은 연속된 두 날짜를 나란히 표시하고 세로 태블릿과 휴대폰은 한 날짜를 표시한다. 각 날짜의 패널 안에는 하루 할 일 최대 5개·30분 일정표·날짜별 자유 기록이 모두 있다. 패널 폭이 600px 이하이거나 휴대폰 가로처럼 높이가 낮으면 내부 `할 일·일정`·`자유 기록` 탭을 사용하고, 충분히 넓으면 두 영역을 함께 펼친다. 표시 날짜 수와 내부 책 페이지 수는 다른 개념이다. 상단 빠른 입력은 보이는 날짜의 첫 빈 줄로, 수정 버튼은 해당 날짜의 편집 패널로 포커스를 이동한다.

- 항상 보이는 `날짜 선택` 버튼은 같은 이름의 달력 대화상자를 연다. 월 탐색은 표시 월만 바꾼다. 날짜 선택은 시작 날짜를 지정하고 첫 날짜를 표시하며, 이전 날·다음 날은 연속 범위를 하루씩 이동한다. `오늘로 돌아가기`는 계정 시간대의 오늘을 따른다. 날짜 버튼의 이름은 `7, 2026년 11월 7일`처럼 년·월·일을 포함하고, `달력 닫기`·Escape 또는 선택 후 닫으면 시작 버튼으로 포커스를 돌린다.
- `1번째 할 일`부터 `5번째 할 일`까지 항상 다섯 줄을 표시하고 첫 빈 줄부터 차례로 현재 날짜에 저장한다. 별도 `할 일 입력`·`할 일 추가` 폼은 없다. 기존 입력함은 이전 기록을 펼쳐 확인하고 `오늘로`·`이날로`로 배정한다. 일정·글 초안은 날짜 이동에도 유지하며, 저장된 제목의 inline 편집 중에는 해당 실행일을 고정한다.
- 완료·취소한 항목도 상단 하루 할 일과 5개 집계에 남는다. 별도 완료 기록은 실제 완료 시각의 날짜에 남는다. 과거·미래 페이지에서 완료하면 실제 완료일을 안내한다.
- 날짜별 목록·커서·초안을 분리하고 표시 범위에 필요한 날짜를 조회한다. 이전 날짜의 지연 응답은 다른 날짜의 목록·상태를 덮지 않는다. 할 일 수정·저장 또는 일정·자유 기록 저장·불확실 요청 복구 대기 중에는 날짜 이동을 제한한다. 일정·자유 기록의 미저장 초안이나 조회 중에는 날짜 이동을 허용한다.
- 기존 API·인증·계정 분리를 유지한다. 날짜별 일반 텍스트 자유 기록을 이번 첫 기능 확장에 포함한다. 06:00~24:00의 고정 36칸 일정은 제공한다. 반복·기간 일정·외부 캘린더, 서식 편집·첨부·검색·회고의 전체 기능은 포함하지 않는다.

## 우선순위와 다이어리 기호 (2026-11-07)

다섯 줄 중 저장된 행은 제목을 같은 입력란에서 편집한다. 빈 줄은 첫 빈 줄만 활성화하고 저장 성공 후 다음 빈 줄을 연다. Enter·Tab·포커스 이동·행의 `할 일 저장`으로 저장하며, 한글 등 IME 조합 중 Enter는 제출하지 않는다. 유효한 새 줄의 Enter·Tab 저장은 다음 빈 줄로 포커스를 옮기며 Shift+Tab은 일반 역방향 탐색이다. 저장·되돌리기 버튼으로 옮기는 포커스는 blur 제출을 중복 실행하지 않는다. 실패·입력 오류가 있으면 제목을 유지하고 다음 줄을 열지 않는다.

위에 놓인 항목이 더 중요한 항목이다. 각 행의 `{제목} 순서 이동` 핸들을 마우스·터치로 원하는 저장 행까지 끌고 놓는다. 이동 중에는 목표 행만 강조하고 원래 목록 순서는 저장 성공까지 유지한다. 위·아래 화살표 버튼은 제거한다. 키보드는 Space로 선택, 위아래 방향키·Home·End로 목표 위치 지정, Space·Enter로 확정하며 Escape·Tab·포커스 이탈은 취소다. 범위 밖 놓기·포인터 취소·배경 목록 변경도 쓰기 없이 취소하고 순서를 유지한다. 상태·제목 수정과 새로고침 후에도 순서를 유지하며 이동 저장 뒤 같은 항목의 핸들로 포커스를 복원한다. 상·중·하 선택과 배지는 없고 기존 priority 값은 내부 호환용으로만 보존한다.

드래그 중에는 날짜 선택·책 페이지 탭·다른 쓰기를 잠근다. 드래그 안내는 별도 `aria-live` 영역에서 읽고 기존 저장 결과의 `role="status"`를 중복하지 않는다. 드래그 중 계정의 오늘이 바뀌면 기존 날짜를 유지하고, 취소 후에는 현재 날짜·시간대와 마지막 조회 기준을 비교해 새 날짜 목록을 다시 읽는다. 저장 후 재조회로 이동 구간의 항목 순서와 버전을 함께 갱신하며 실패·충돌은 기존 복구 선택으로 해결한다.

각 행의 사각형 버튼 `{제목} 상태 변경`은 `{제목} 상태 선택` 그룹을 연다. `완료`·`미루기`·`진행 전`·`취소`를 선택할 수 있으며 Escape로 닫으면 원래 상태 버튼에 포커스를 돌린다. 상태를 색이나 모양만으로 전달하지 않고 버튼 이름과 메뉴 텍스트로 구별한다.

| 실행 상태 | 표시 |
|---|---|
| 진행 전(open) | □ 진행 전 |
| 완료(completed) | ✓ 완료 |
| 미룸(deferred) | → 미룸 |
| 취소(canceled) | × 취소 |

유형 선택 메뉴와 유형 이름·기호는 모든 화면에서 제거한다. 목록·수정 패널·기호 안내의 open 상태는 기존 kind 값과 관계없이 `□ 진행 전`으로 표시한다. 수정 패널에서는 제목·실행 예정일·마감일·진행 상태를 편집한다. 이전 기록의 기존 상태 선택·완료 취소·취소 복원 조작은 유지한다.

## 실행일·마감일과 계획 이력 (V-15)

`실행 예정일`은 언제 할지, `마감일`은 언제까지 해야 하는지를 나타내는 별도 날짜 입력이다. 각각 선택 사항이며 빈 값은 해당 날짜만 해제한다. 마감일을 바꿔도 실행일이나 줄 중요도를 자동 변경하지 않는다. 실행일이 마감보다 늦어도 사용자가 의도한 계획을 저장할 수 있으며 두 날짜를 같은 필드로 합치지 않는다. 기존 충돌 비교에는 최신 실행일·마감일과 내 변경을 함께 표시한다.

상단 다섯 줄은 선택 날짜에 실행하도록 배정한 과제이며 마감일이 있으면 줄에서 확인할 수 있다. `마감만 이 날`은 마감은 선택 날짜이지만 실행일이 다른 날이거나 없는 진행 전·미룸 과제를 보여 주는 별도 목록이다. 같은 날짜에 실행·마감하는 과제는 상단 줄에만 남기며 마감만 목록과 다섯 줄 수를 합산하지 않는다. 완료·취소 과제는 마감만 목록에서 빠진다. 이 목록에서도 원본 수정과 상태 변경에 접근한다.

과제의 계획 변경 이력은 읽기 전용 목록으로 최신부터 표시한다. 종류·발생 시각·실행일/마감일/상태의 이전→이후 값을 읽을 수 있고 완료 시각은 계정 시간대를 따른다. 중요도 순서는 변경 사실을 표시하며 내부 순서값·버전은 API/DB 스냅샷으로 보존한다. 새 과제의 최초 계획은 생성 기록에 남으며 미래 계획을 현재 완료하거나 나중에 다시 옮겨도 과거 계획은 유지된다. 기존 details=null 활동은 `이전 기록: 변경 전후 값 없음`으로 안내한다. 알려지지 않은 옛 날짜를 현재 과제 날짜로 표시하지 않는다.

이력은 더 보기, 조회 중, 조회 실패와 재시도를 구별한다. 과제나 계정이 바뀌면 이전 조회를 폐기하고 늦은 응답으로 새 화면을 덮지 않는다. 이력 조회 자체는 편집 내용이나 과제 버전을 변경하지 않는다. 저장 중·미확정 응답·충돌의 전역 잠금과 내 변경 보존을 유지하며, 좁거나 낮은 화면에서 추가 필드와 긴 이력은 패널 내부에서 탐색한다. 문서 바깥 스크롤을 만들지 않고 키보드로 날짜·저장·이력·복구 조작에 접근해야 한다.

미룸을 선택하면 `→`를 표시하고 실행 예정일을 유지한다. 날짜 이동은 수정 패널의 실행 예정일에서 수행하도록 안내한다. 취소는 실행일의 하루 계획에 `×`로 남고 이전 미완료에서는 빠진다. `취소 되돌리기` 또는 진행 전 선택으로 `□ 진행 전`을 복원한다. 완료 취소와 취소 상태를 서로 구별한다.

날짜 없는 비완료 항목에는 `정리 완료`를 제공하지 않는다. 날짜 없는 완료 항목을 미완료·미룸·취소로 변경하거나 비완료 항목의 실행일을 지우면 입력함에 유지·복귀시켜 다시 수정할 수 있게 한다. 직접 API로 이 조건에서 정리 완료를 요청하면 422로 거절한다.

저장된 제목의 inline 편집 또는 수정 패널이 열려 있는 동안 다른 행 입력·순서·상태·완료·정리·다른 수정 버튼, 신규 저장, 시간대 저장, 일정·자유 기록 편집·저장과 날짜 탐색은 잠근다. inline 편집은 `할 일 저장`과 `입력 되돌리기`를 제공한다. 현재 패널의 필드·변경 저장·수정 닫기는 계속 사용할 수 있다. 저장 성공을 확인한 뒤 편집을 닫으며 실패·충돌 시 입력을 보존한다. 로그아웃·테스트 나가기는 기존의 미저장 입력 확인을 따른다.

inline 편집 중에는 원래 제목·버전·실행일 스냅샷을 유지한다. 배경 새로고침은 세션만 확인하고 목록 교체를 보류하므로 원격 제목·날짜 변경으로 초안이 다른 줄에 붙지 않는다. 자정·외부 시간대 변경에도 편집 날짜를 고정하고, 일시 401이면 초안을 보존한 채 비활성화한다. 같은 계정이 복구되면 계속 편집하며 실제 계정 변경에서는 이전 초안을 폐기한다. 저장에는 편집 시작 버전을 사용하고 412 충돌이면 최신 항목과 내 변경을 비교해 선택한다.

## 화면과 이동

로그인 → 오늘 화면으로 진입한다. 최초 목표 설정을 요구하지 않는다. Google 로그인 취소·공급자 오류 시 로그인 화면에 머물고 재시도 경로를 제공한다.

각 날짜 패널에는 그 날짜·시간대, 하루 할 일, 36칸 하루 일정, 자유 기록을 둔다. 공통 상단에는 현재 범위·날짜 선택·이전/다음 날·로그아웃을 두고 목록 새로고침은 날짜별로 제공한다. 시간대 설정은 첫 날짜 패널에만 제공한다. 이전 입력함·완료 기록·이전 미완료는 `이전 기록과 입력함`을 펼쳐 접근한다. 목표·통계의 빈 메뉴는 노출하지 않는다.

```text
날짜 D의 패널 내부                       날짜 D의 자유 기록
2026-11-07 · Asia/Seoul [날짜 선택]        오늘의 기록 · 2026-11-07
오늘의 할 일                     0 / 5   자유롭게 쓰는 글
[□] [1번째 할 일: 제안서 초안] [⠿]  [생각, 메모, 하루의 이야기를 작성…]
[□] [2번째 할 일: 입력 가능  ]          글자 수 / 10,000자      [글 저장]
[□] [3번째 할 일: 대기       ]
[□] [4번째 할 일: 대기       ]
[□] [5번째 할 일: 대기       ]
하루 일정 [‹] [06:00–08:00 ▼] [›]       글 저장 상태와 복구 경로
06:00–06:30 [일정 입력                 ]
06:30–07:00 [일정 입력                 ]
07:00–07:30 [일정 입력                 ]
07:30–08:00 [일정 입력                 ]
                              [일정 저장]
▸ 이전 기록과 입력함
```

현재 화면의 제목 입력은 선택 날짜로 바로 저장하며 입력함을 거치지 않는다. 날짜를 생략한 과거 API 생성은 여전히 입력함에 저장된다. 기존 입력함에서 `오늘로` 또는 `이날로`를 선택하면 실행일과 정리 완료를 함께 적용한다. 수정 폼에서 날짜만 변경하는 경우에는 정리 여부를 자동 변경하지 않는다. 전체 컬렉션 기능은 포함하지 않는다.

## 하루 할 일 한도와 36칸 일정 (V-12·V-14)

상단 하루 할 일은 `현재 개수 / 5`를 표시한다. 완료·취소도 한 자리를 차지하고 날짜에 지정된 모든 상태를 보여 준다. 5개를 채우면 여섯 번째 줄을 만들지 않는다. 저장된 다섯 줄의 제목·상태·순서는 계속 수정할 수 있다. 날짜 이동으로 자리가 생기면 다시 추가할 수 있으며, 가득 찬 날짜로 이동하는 요청은 실패 사유와 현재 편집을 보존한다. 기존에 5개를 넘은 기록은 `이전에 저장한 추가 할 일`을 펼쳐 모두 읽고 수정할 수 있게 하며 삭제하지 않는다. 다른 날짜로 옮긴 항목은 대상 날짜의 마지막에 붙는다.

`하루 일정`은 `06:00 일정`부터 `23:30 일정`까지 총 36칸이며 2시간·4칸씩 9페이지로 나눈다. 현재 4칸만 화면에 표시하고 `일정 시간대` 선택(06:00–08:00부터 22:00–24:00)과 `이전 시간대`·`다음 시간대` 버튼으로 이동한다. 첫·마지막 페이지의 경계 버튼은 비활성이다. 24:00은 끝 경계로만 표시한다. 날짜 변경 시 첫 시간대로 돌아가지만 시간대 페이지 전환은 미저장 슬롯을 지우지 않는다. 저장 불확실·충돌 중에도 페이지를 옮겨 내 첫 칸과 마지막 칸을 비교할 수 있다.

각 칸은 한 줄 제목 200자 이내이며 저장 시 NFC 정규화와 앞뒤 공백 제거를 적용한다. 빈 칸은 배열에 넣지 않는다. 현재 보이지 않는 페이지를 포함한 날짜 전체 슬롯을 `일정 저장`으로 함께 저장한다. 칸을 지우고 저장하면 해당 칸만 삭제되며, 날짜마다 별도 일정과 초안을 유지한다. 저장된 배열과 같으면 저장 버튼은 비활성이고 저장 후 `일정을 저장했습니다.`를 표시한다. 자동 저장이나 알림·캘린더 이벤트 생성은 수행하지 않는다.

일정의 초안·이탈 확인·계정 전환·일시 401 보존·지연 응답·pending 날짜 고정은 자유 기록과 같은 화면 규칙을 따른다. 일정 저장·복구 대기 동안 할 일과 자유 기록 변경도 잠근다. 조회 실패는 `일정 다시 불러오기`, 불확실 저장은 `같은 일정 다시 저장`·`일정 저장 여부 확인`, 412 충돌은 `저장된 일정 사용`·`내 일정 다시 저장`으로 해결한다. 24시간 지난 불확실 요청은 재전송하지 않고 저장 여부를 먼저 확인한다.

일정 저장 알림은 `.schedule-save-status`의 `aria-live="polite"`로 전달한다. 입력 라벨에는 시작 시각을 넣고 화면에서는 끝 시각도 함께 표시한다. 기존 할 일의 `role="status"`를 중복 추가하지 않는다.

## 날짜별 자유 기록 (V-13)

자유 기록은 별도 `자유 기록` 영역에 일반 텍스트 입력란 `자유롭게 쓰는 글`과 `글 저장` 버튼을 제공한다. 각 날짜에 한 편을 작성하며 자동 저장하지 않는다. 본문이 저장된 내용과 같거나 초기 빈 글이면 저장 버튼을 비활성화한다. 기존 내용을 모두 지운 빈 글은 변경으로 저장할 수 있다. 최대 10,000 Unicode 코드 포인트를 세며 NUL을 허용하지 않는다. CRLF를 LF로 바꾸는 것 외에는 공백·빈 줄·마지막 줄바꿈을 유지한다.

날짜 이동 시 각 날짜의 미저장 본문은 같은 계정의 탭 메모리에 보존한다. 돌아왔을 때 초안을 보여 주고 과거 날짜의 늦은 응답으로 현재 글을 교체하지 않는다. 저장된 글은 새로고침 후 불러오지만 미저장 초안은 영구 보관하지 않는다. 현재 날짜가 아닌 다른 날짜에 초안이 있어도 새로고침·이탈·로그아웃·테스트 나가기는 확인을 요구하며, 이탈을 확정하면 초안을 잃을 수 있다. 다른 계정에서는 이전 글이나 초안을 표시하지 않는다. 일시적인 401은 본문을 지우지 않고 편집을 잠그며, 같은 계정으로 목록 새로고침 등 세션 확인이 복구되면 초안을 계속 쓸 수 있다. 실제 계정 전환 또는 성공한 로그아웃에서만 계정 캐시를 폐기한다.

| 글 상태 | 표시와 행동 |
|---|---|
| 조회 중 | 글을 불러오는 중 안내, 본문 입력 잠금. 날짜 탐색은 허용 |
| 없는 날짜 | 빈 입력란과 안내. 저장된 글이 없는 정상 상태이며 오류와 구별 |
| 미저장 초안 | 글 저장 활성화, 날짜 이동 허용, 날짜별 초안 보존 |
| 저장 중 | `글을 저장하는 중입니다.`. 본문·날짜·할 일·일정 변경·시간대 저장 잠금 |
| 저장 성공 | `글을 저장했습니다.`. 서버 재확인 후 저장 버튼 비활성화 |
| 조회 실패 | 오류와 `글 다시 불러오기`. 빈 글로 성공 처리하지 않음 |
| 저장 불확실 | 본문과 요청 키·버전 보존, `같은 글 다시 저장`·`저장 여부 확인`. 날짜와 다른 변경 잠금 |
| 24시간 지난 불확실 요청 | 자동·수동 재전송 차단, 저장 여부 확인으로 최신 본문과 비교 |
| 충돌 | 저장된 글과 내 글을 비교. `저장된 글 사용` 또는 `내 글 다시 저장`으로 해결 |

`저장 여부 확인`에서 서버 본문이 내 글과 같으면 완료로 복구하고 잠금을 해제한다. 다르면 두 글을 비교하는 선택을 제공한다. `내 글 다시 저장`은 최신 버전과 새 요청 키로 시도하며, `저장된 글 사용`을 선택하기 전에는 내 글을 버리지 않는다. 단순 미저장 상태는 잠금 사유가 아니며 저장·불확실 결과·충돌은 복구 버튼 없이 무한히 잠그지 않는다.

저장·불확실 요청을 복구하는 동안 표시 날짜와 조회 날짜는 해당 요청의 날짜에 고정한다. 자정 경과·다른 기기의 시간대 변경으로 계정의 오늘이 달라져도 다른 날짜의 본문을 표시한 채 이전 글의 복구 버튼을 제공하지 않는다.

글 저장 알림은 `.journal-save-status`의 `aria-live="polite"`로 전달하며 기존 할 일의 `role="status"`와 구별한다. 입력란·버튼·오류에는 접근 가능한 이름과 연결을 제공한다. 본문은 HTML이나 Markdown으로 렌더링하지 않는다.

## 접근성과 모바일

두 날짜 조건은 폭 700px 이상이면서 hover·fine pointer인 PC, 또는 폭 900px·높이 600px 이상인 가로 화면이다. PC 1366×768·707×978 및 터치 태블릿 1024×768은 두 날짜, 터치 태블릿 768×1024와 휴대폰 390×844·844×390은 한 날짜다. 9999-12-31은 화면이 넓어도 한 날짜만 표시한다.

한 날짜 화면에서는 마지막 사용 날짜를 유지하고 `다른 날짜 보기`로 반대 날짜를 열 수 있다. 저장 불확실·충돌·편집·드래그 중인 날짜는 회전 후 자동으로 보여 주며 다른 날짜 보기와 범위 이동을 잠근다. 해당 날짜의 복구 버튼은 계속 접근할 수 있다. 각 날짜는 위치가 아니라 날짜 자체로 유지하므로 둘째 날짜가 첫째 자리가 되거나 화면 밖으로 나갔다가 돌아와도 그 날짜의 초안을 그대로 표시한다.

패널 안의 600px 기준 내부 탭과 낮은 가로 화면 구성은 모든 편집기를 유지한 채 표시만 바꾼다. 한 화면에 다섯 줄과 일정 현재 네 칸·저장·날짜 선택을 조작할 수 있어야 한다. 바깥 문서 스크롤 없이 긴 글·이전 기록·오류 복구는 독립 영역에서 끝까지 접근한다. 숨긴 날짜까지 ID와 label 및 aria-describedby 연결을 고유하게 유지하고, 두 날짜의 제목이 같아도 포커스와 상태 조작은 해당 날짜에만 작용한다. 키보드·마우스·터치와 날짜별 접근성 알림을 검수한다.

## 검토 항목

이 문서는 와이어프레임의 정보 구조다. 실제 픽셀 디자인, 터치 타깃, 포커스 이동과 스크린리더 결과는 구현·UX 검토에서 확인한다. 하루 할 일의 정렬은 상태와 관계없이 dailyOrder·생성 시각·ID 오름차순, 별도 완료 기록은 완료 시각 내림차순이며 ID로 동률을 정렬한다.

## 로그인 중지 중 로컬 체험 경로 (2026-11-07)

사용자가 Google 로그인 없이 화면을 테스트할 수 있도록 개발 환경에서 명시적으로 켠 `/demo` 진입을 제공한다. 로그인 화면의 활성 `로그인 없이 테스트하기` 링크로 같은 플래너 UI에 진입하며 입력·수정·실행일·완료·완료 취소·시간대 변경과 날짜별 일정·자유 기록 저장을 수행한다. 저장 위치는 브라우저 탭의 sessionStorage로 표시하고 새로고침 후 복원한다. 저장소 접근·저장 실패는 성공으로 표시하지 않는다.

실제 API·인증 쿠키·DB와 연결하지 않으며 계정 자료로 이전하지 않는다. 운영 빌드는 항상 404이고 개발 환경에서도 로그인 중지와 명시적 데모 설정이 모두 필요하다. Google OAuth 및 실제 서버 저장 검수는 별도로 유지한다.

기존 v1 체험 기록은 같은 저장 키로 읽으며 누락된 priority·kind를 medium·task로 보충한다. priority·kind는 내부 자료 호환용으로 보존하고 화면에는 표시하지 않는다. dailyOrder가 없으면 owner·날짜별 생성 시각·ID 순으로 보충하며 날짜가 없으면 null이다. 읽기만으로 저장 원문을 덮어쓰지 않고 성공한 변경에서 새 스키마로 저장한다. 제목·날짜·완료 상태·원본 ID를 유지하며 저장 실패나 잘못된 저장 자료를 빈 기록으로 덮어쓰지 않는다.

체험의 저장된 자유 기록도 탭 sessionStorage에 보관하며 날짜별로 읽는다. 기존 체험 기록에 자유 기록이 없으면 빈 기록 집합으로 읽고, 성공한 저장에서만 새 형식으로 보존한다. 미저장 글은 제품 경로와 마찬가지로 메모리 초안이며 이탈 확인 후에는 유지되지 않을 수 있다.

기존 체험 자료에 일정이 없으면 빈 일정 집합으로 읽는다. 5개를 넘는 과거 할 일도 읽기·수정은 보존하고 새 배정만 제한한다. 성공 저장에서만 일정과 과제 변경을 새 체험 형식에 보관하며 제품 API를 호출하지 않는다.
