# 마감일·계획 변경 이력 검증

기준일 2026-11-10 · 명세 0.11 · API 0.10.0 · CR-0004

현재 상태: **이번 구현 단위의 로컬 최종 검수 완료**. 실제 PostgreSQL을 포함한 전체 check 179개, 제품 브라우저 전체 66개, 체험 브라우저 전체 28개, 기본 브라우저 10개로 총 283개가 통과했다. 명세·린트·타입 검사와 운영 빌드도 성공했다. 제품과 체험은 각각 최종 한 번의 전체 실행으로 확인했고 이전 부분 재검증을 합산한 수치가 아니다. 이 문서는 로컬 실행 증거이며 최신 커밋의 원격 CI 결과는 [PR #4 Checks](https://github.com/haesikryu/web-planner/pull/4/checks)에서 별도로 확인한다.

## 검증 범위

- 마감일 생성·수정·해제와 실행일/마감일 양방향 독립성, 올바른 달력 날짜·null·생략·범위 경계.
- 실행일 다섯 줄과 마감만 해당 날짜인 open/deferred 목록 분리, 같은 날짜 중복 제외와 완료/취소 제외, 계정 격리·커서 페이지.
- 과제 생성 및 실제 날짜·상태·순서 변경의 before/after/version, 미래 계획의 현재 완료와 원래 계획 보존, 완료 취소의 유효 활동 연결.
- 같은 값·같은 요청 재생의 무증가, 오래된 버전·5개 한도·중간 DB 실패·동시 쓰기에서 활동과 원본의 원자성.
- 기존 활동의 details=null 보존과 새 JSON 제약, 기존 과제·기록·일정·요청 재생 자료 보존.
- PC·모바일 수정 폼, 두 날짜 목록, 이력 조회/더 보기/실패 복구, 계정·과제 전환 지연 응답 차단, 저장 충돌 초안 보존과 키보드/화면 높이 회귀.
- 체험 저장소의 독립 저장·이전 형식 호환과 실패 보존. 실제 서버 테스트와 분리.

로컬 최종 합계는 179+66+28+10=283개다. 위의 과제 API·마이그레이션 66개는 check 179개에, 신규 제품 6개와 실패 사례 재검증 2개는 제품 전체 66개에 포함된 범위이므로 합계에 다시 더하지 않는다.

실행은 실제 사용자 자료와 분리된 합성 계정·테스트 DB에서 수행한다. Node 24, PostgreSQL 18, Vitest와 Playwright를 사용하며 제품 브라우저는 합성 사용자에 대한 실제 서비스 세션을 이용한다. 체험은 별도 탭 저장소를 사용한다. 환경 비밀값과 실제 사용자 내용은 검증 기록에 넣지 않는다.

## 발견한 문제와 수정 확인

**목록 커서의 시각 정밀도.** PostgreSQL의 마이크로초 시각을 JavaScript Date의 밀리초로 줄여 다음 페이지 경계에 쓰면 같은 밀리초에 생성된 행이 반복되거나 누락될 수 있었다. 과제 목록과 활동 목록의 커서에는 DB 시각의 6자리 소수부를 유지하고 SQL 경계 비교에 사용한다. 기존 3자리 서명 커서도 허용하며 해당 소유자의 같은 anchor 행과 밀리초 시각이 일치하면 원래 정밀도를 복원한다. 응답의 표시 시각 형식과 기존 정렬·커서 scope는 유지한다. due·day·completed의 limit=1 페이지, 동일/근접 마이크로초와 이전 커서를 직접 검증했다.

**팝업 겹침.** `마감만 이 날`과 `이전 기록과 입력함`을 동시에 열어 조작 영역을 가리는 문제를 수정했다. 한 목록을 열면 다른 목록을 닫고 과제 수정 진입 때 목록을 닫아 편집·이력과 복구 조작에 접근하게 했다. 저장 잠금과 내부 스크롤을 유지하면서 새 제품 PC/모바일 흐름을 다시 확인했다.

**날짜 표기 회귀 검사의 기대값.** 실행일과 마감일을 구별하도록 미지정 표기를 `실행일 미정 · 마감일 없음`으로 바꿨지만 일부 기존 검사에는 `날짜 미정`이 남아 있었다. 제품·체험의 해당 기대값을 갱신했고 제품 실패 2개를 재검증했다. 검사 시간을 늘리거나 실패를 무시한 결과가 아니며, 최종 전체 실행 여부는 위 표에서 구분한다.

**체험 초기 로딩.** 체험 전체 첫 실행의 1개 실패는 초기 개발 서버 로딩과 연속 재기동 과정에서 화면 준비가 5초 기대 범위를 넘긴 사례였다. 서버 준비 후 같은 PC/모바일 사례 2개가 통과했고 이어 최종 전체 28개도 통과했다. 부분 재실행을 전체 통과로 합산하지 않았다.

**실제 로컬 화면 확인.** localhost:3000의 브라우저에서 마감일을 입력해 저장하고 계획 변경 이력의 전후 날짜를 확인했다. 이 수동 확인은 실제 화면 조작 증거이며 Google 공급자 로그인·운영 배포 또는 전체 데이터베이스 검수의 대체 증거는 아니다.

관련 구현은 `src/domain/task-history.ts`, `src/server/product/tasks.ts`, `migrations/0006_task_plan_history.sql`, `src/app/task-history.tsx`, `src/app/planner-day.tsx`, `src/app/demo/transport.ts`다. 자동 검증은 `tests/unit/product-api.test.ts`, `tests/unit/task-history-migration.test.ts`, `tests/unit/demo-transport.test.ts`, `tests/e2e/planner.spec.ts`, `tests/e2e/demo.spec.ts`와 연결한다.

## 요구 판정 경계

FR-04-02·FR-05-03·FR-12-02는 각각의 전체 검수기준 충족 여부로 판단한다. FR-05-02는 이미 통과한 마감일 보존 요구의 회귀 범위다. FR-05-01은 마감일을 추가해도 본문·예상 시간·목표·컬렉션·태그가 남으므로 개발중을 유지한다. FR-12-03은 회고 중단/재개 요구이므로 이번 이력 구현에 연결하지 않는다.

이번 로컬 검수는 FR-04-02와 FR-05-03의 완료·통과 판정 근거를 충족한다. 관리표의 직전 27/92에서 두 요구를 반영하면 29/92=31.5%다. FR-12-02는 원본 ID 유지·날짜 변경 활동 기준으로 이미 완료·통과였으므로 이번 스냅샷·조회 증거 보강을 완료 수에 다시 더하지 않는다. 본 커밋 작성 시점의 관리표 반영은 원격 CI 확인 뒤 수행할 예정이며 분모 92개와 폐기 1개의 원문 이력을 유지한다.

실제 Google 공급자 로그인·운영 배포·운영 부하·사용자 인수승인은 별도 대기다. 로컬·합성 계정 검증을 이 외부 검증의 통과로 표기하지 않는다.
