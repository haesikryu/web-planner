기준일: 2026-11-07. T-005~T-009 구현, T-010 자동 검증, T-004 PostgreSQL 서버·복원 검증 기록이다. 실제 Google 계정의 OAuth와 배포 환경은 별도 통과 조건이다.

이전 단계의 중요한 검사가 통과한 후 다음 작업을 진행했다. 외부 OAuth 미설정을 합성 검증으로 통과 처리하지 않았다.

## 실행한 검사

- `npm run check`: PGlite 기본 실행은 40개 통과·별도 PostgreSQL 연결 시험 1개 생략이다. 실제 PostgreSQL URL을 지정하면 41개 모두 통과한다. 명세·린트·타입도 통과했다.
- `PLANNER_TEST_DATABASE_URL=... npm run check`: Docker PostgreSQL 18의 서로 다른 연결에서 동시 수정 200/412, 처리 중 키의 409·Retry-After, 같은 키의 재생·만료, 실패한 활동 쓰기의 전체 롤백을 확인했다.
- API 응답은 구현과 별개인 OpenAPI 0.4.0의 JSON Schema를 Ajv 2020으로 검증한다. 선언되지 않은 상태·누락 필드·추가 필드·형식·ETag·no-store 오류를 검사한다. 구조 검사 스크립트는 계속 구조 확인만 담당한다.
- `npm run test:e2e:product`: 실제 PostgreSQL과 서비스 자체 세션으로 PC·360px 모바일 16개 통과. 합성 계정·세션은 테스트가 DB에 준비하며 앱에는 테스트용 로그인 경로가 없다.
- `npm run build`: 통과. 안내 화면·기본 API·접근성 회귀 10개도 통과했다. GitHub CI는 원격 실행 후 별도 기록한다.

## 중요한 실패와 조치

1. 성공 응답 유실: DB 커밋 후 응답을 의도적으로 차단했다. 화면은 입력·원래 요청 키를 보존하고 재시도 성공 시 원본 한 개만 표시한다. 24시간 이후에는 요청을 보내지 않는다.
2. 동시 수정: 오래된 버전은 412로 거부한다. 최신 항목과 내 변경을 비교한 뒤 사용자 선택으로 새 버전·새 키를 사용한다.
3. 저장 중 오류: 테스트 DB 트리거로 활동 INSERT를 실패시켰다. 과제·활동·키 모두 롤백됐고 같은 키로 정상 재시도했다. 원문 SQL 오류는 응답에 없다.
4. 계정 변경: 브라우저의 실제 세션을 다른 합성 사용자로 전환했다. 기존 목록·입력·보류 요청을 지우고 새 계정 화면으로 이동했다.
5. 접근성: 안내 문구의 색 대비와 로고의 읽기 이름 오류를 발견해 수정했다. 자동 WCAG A/AA 검사를 통과했으며 수동 스크린리더 적합성 전체를 인증한 것은 아니다.
6. 테스트 실행: Next의 기본 알림 영역과 테스트 탐색자가 충돌한 문제와 Playwright 작업자 간 DB 풀 수명 문제를 수정했다. 제품 동작과 테스트 인프라 결함을 구분했다.
7. 초기 목록 로딩 완료가 최신 저장 실패 안내를 덮어쓰는 경합을 발견했다. 상태 갱신 세대를 구분해 오래된 작업의 안내를 무시하고, 실제 실패 안내 검증을 유지한 채 PC·모바일 전체 16개를 다시 통과했다.

기존 GitHub CI는 PR #4에서 통과했다. 실제 PostgreSQL·제품 E2E를 추가한 설정안은 docs/ci/planner-verification.yml에 있으며, 연결 앱의 workflow 쓰기 권한 403과 잠긴 Mac으로 아직 실행 경로에 적용하지 못했다. 기존 원격 검사와 로컬 실제 DB·제품 브라우저 검증을 구분한다.

## 구현 제약과 남은 조건

- 실제 Google OAuth 클라이언트·동의 화면·테스트 사용자와 가입 대상 D-01이 필요하다. 신규 가입은 기본 차단이다.
- 운영 호스팅·도메인·비밀 관리·HTTPS·백업 주기·관측·부하 기준은 미확정이다. 이 기록은 배포 또는 수용 승인이 아니다.
- 자동 접근성 검사는 보조 증거다. 수동 키보드·스크린리더·장애 대응의 출시 검토는 별도다.
- 테스트 DB는 loopback의 별도 이름만 허용한다. 실제 사용자 데이터를 쓰지 않았다. Docker는 설치된 엔진을 기동해 일회용 컨테이너로 실행했다.
- 과제 이외의 일정·메모·가치·목표·회고 전체 요구는 구현 완료로 계산하지 않는다.

만료 정리 명령은 실제 테스트 DB에서 만료 요청·OAuth state·세션 각각 1개만 삭제했고 사용자 2명·과제 1개·유효 요청 기록 1개는 보존했다. 목록 로딩 도중 시간대가 변경되는 경쟁 조건도 PC·모바일에서 재현해 이전 기준 결과를 버리는 것을 확인했다.

## 본인 전용 베타 접근 정책 회귀 (2026-11-07)

D-01 확정 후 `AUTH_ALLOWED_EMAILS`를 필수 설정으로 추가했다. 검증된 Google 이메일만 로그인할 수 있고 기존 세션도 허용 목록에서 제외되면 폐기한다. 값 누락·와일드카드·빈 목록 항목 차단, 별칭 자동 확장 금지, 서명 유효하지만 미허용 이메일 차단, 기존 세션 철회를 검사했다. 실제 PostgreSQL 포함 47개·제품 PC/모바일 16개·기본 PC/모바일 10개와 빌드가 모두 통과했다. 제품 E2E는 명시적으로 열거한 합성 이메일만 허용하며 인증 우회 경로를 추가하지 않는다.

Mac 잠금 해제 후 기존 로그인 Chrome으로 CI 편집을 시도했으나 GitHub 파일·편집 페이지 본문이 빈 화면으로 표시됐다. 정상 PR 탭을 통한 접근과 새로고침 후에도 편집 내용을 확인할 수 없어 저장하지 않았다. 준비된 `docs/ci/planner-verification.yml`은 아직 실제 워크플로에 반영되지 않았다. 이는 기존 통합 앱의 workflow 쓰기 403과 구분되는 브라우저 표시 문제다. 기존 CI와 이번 로컬 PostgreSQL·브라우저 실행 결과를 구분한다.

## 2026-11-07 우선순위·유형·상태 기호

- 상·중·하 우선순위, □ 할 일·△ 약속·○ 행사 유형, ✓ 완료·→ 미룸·× 취소 상태를 명세 0.3·V-12·OpenAPI 0.5.0에 연결했다. 미룸은 실행일을 유지하고 취소 항목은 원래 실행일에 표시하되 이전 미완료 목록에서 제외한다.
- `PLANNER_TEST_DATABASE_URL=... npm run check`: 명세·린트·타입 및 실제 PostgreSQL 18 포함 단위/계약/통합 71개 통과. 기존 요청 해시·과거 응답 재생, 버전·활동·완료시각·잘못된 상태 거절, 데이터 변경 실패 롤백을 검사했다.
- 기존 DB 스키마에서 마이그레이션 0002를 적용해 제목·상태·실행일·버전을 보존하고 medium/task 기본값을 보충하는 회귀 검사를 통과했다. 기존 sessionStorage v1 자료도 읽고 성공한 저장에서만 v2로 전환한다. 사용 중인 데모 탭의 기존 항목 2개가 유지된 화면을 확인했다.
- 제품 PC/360px 모바일 브라우저 22개, 데모 10개, 운영 빌드와 기본 화면 10개 통과. 우선순위·유형·상태 변경, 새로고침 보존, 취소·완료 취소 복원, 날짜 없는 항목의 입력함 복귀, 편집 중 다른 변경 차단을 검증했다.
- 검토 중 편집 중인 제목이 다른 항목 저장으로 닫힐 수 있던 문제와 날짜 없는 정리된 완료 항목의 복원 후 목록 접근이 끊기는 문제를 수정했다. 편집 중 다른 쓰기를 잠그고, 날짜 없는 비완료 항목은 입력함에 유지하며 명시적인 숨김 요청은 422로 거절한다. 서버가 보충한 입력함 복귀도 버전·활동으로 기록하고 원래 요청 해시를 보존한다.
- 첫 브라우저 실행의 편집 선택 상자 이름 불일치는 명시적 접근성 이름으로 수정했다. 데모 안내 문구 기대값을 실제 문구에 맞췄다. 제품 초기 실행 3건의 지연은 trace의 성공 응답과 개발 서버 첫 컴파일 시간을 확인한 뒤 최초 목록 준비·시간대 응답에만 제한된 대기를 적용했다. 재실행에서 전부 통과했다. 타입 생성과 개발 서버 시작의 병렬 실행으로 발생한 생성 파일 경합은 실행 순서를 분리했다.
- 로컬 개발 DB는 비공개 작업 폴더에 pg_dump 백업 후 0002를 적용했다. 적용 전후 과제 0개·활동 0개 유지, 마이그레이션 이력 2→3 및 새 컬럼 기본값을 확인했다. 데모 자료는 DB와 별개이며 초기화하지 않았다.
- 이번 기록은 로컬 검증이다. 실제 Google 로그인은 중지 상태이며 성공 검증이 남아 있다. 원격 CI는 기존 검사 범위로 별도 확인하며 제품 PostgreSQL·데모 브라우저 CI 확장은 기존 대기 상태다.

## 2026-11-07 제목 입력과 목록 우선순위로 간소화

- 최신 사용자 요청에 따라 생성·수정·목록·충돌 안내·기호 안내에서 유형 선택과 표시를 제거했다. 진행 전 기호는 기존 내부 kind 값에 관계없이 □로 통일했다. 제목만 등록하며 우선순위 기본값은 중이다. 오늘 또는 선택 날짜의 할 일 목록에서만 상·중·하를 편집한다. 수정 폼은 제목·실행일·진행 상태를 받는다.
- DB/API·브라우저 저장 형식은 변경하지 않았다. 기존 kind는 내부 호환용으로 보존하고 UI가 생성·수정 요청에 kind를 보내지 않는다. 제목 수정은 기존 우선순위를 덮어쓰지 않는다. 명세 0.4와 V-12의 검수 항목을 맞췄다.

- 제목만 등록 → 오늘 배정 → 기본 중 확인 → 목록에서 상·하 변경 → 새로고침 유지, 수정 중 다른 작업 잠금, 상태 복원 및 기존 appointment 자료의 공통 기호 표시·제목 수정 후 원본 보존을 확인했다. 현재 사용 중인 데모 탭에서도 입력폼 단순화와 기존 2개 항목 보존을 확인했다.
- 첫 제품 실행에서 오늘 배정 후 목록 확인 1건이 5초 대기 한도를 넘었다. trace에서 첫 PATCH가 약 3.68초 후 200, 후속 목록도 동일 ID·version 2·정상 실행일로 200을 반환한 것을 확인했다. 해당 동작만 정확한 PATCH 응답을 최대 10초 기다려 200을 검사한 뒤 기존 화면 검증 5초를 수행하도록 보완했다. 제품 전체 재실행 24개가 통과했다. 전역 제한이나 제품 저장 동작은 변경하지 않았다.
