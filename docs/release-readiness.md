# 첫 기능 베타 진입 조건

현재 첫 기능의 로컬 구현·자동 검증을 마쳤다. 서비스 공개와 실제 OAuth 성공 검증은 남아 있다. Google 프로젝트·웹 클라이언트와 로컬 설정은 완료했으며, 현재 사용자 요청에 따라 로컬 Google 로그인을 중지하고 `/demo`에서 화면을 검수한다.

| 항목 | 현재 상태 | 다음 증거 |
|---|---|---|
| 제목·날짜·설정·과제·입력함·오늘·완료 취소 | 구현·자동 검사 통과 | PR 검토 |
| 트랜잭션·중복 키·동시 수정·소유자 격리 | PostgreSQL 18 통과 | 배포 환경 재검증 |
| 실제 DB 백업·별도 복원 | 합성 로컬 DB 통과 | 운영 복원 주기·실제 환경 시험 |
| Google 공급자 | 합성 서명·콜백·실제 세션 HTTP 통과 | 설정된 OAuth 클라이언트로 실제 로그인 오류 조사·사용자 시험 |
| 가입 대상 D-01 | 본인 전용 비공개 베타 확정·허용 목록 구현 | 실제 본인 로그인 및 타 계정 거부 확인 |

## 만료 자료 정리

`npm run db:prune`은 지정 환경의 만료 요청 재생 기록·OAuth state·유휴/절대 만료 세션을 각 5,000개까지 한 트랜잭션에서 정리한다. 사용자·과제·활동은 삭제하지 않는다. 출력은 삭제 개수뿐이며 비밀·본문은 출력하지 않는다. 실행 주기는 호스팅 선정 후 정하며 아직 스케줄러를 만들지 않았다. 정리 지연 중에도 만료 키는 재생되지 않고 만료 세션은 API에서 거부된다.

## 실제 OAuth 검증 순서

1. Google Cloud의 웹 앱 OAuth 클라이언트와 테스트 사용자를 준비한다.
2. 비밀값을 채팅·PR·일반 Drive 문서에 보내지 않고 무시되는 로컬 환경 또는 배포 비밀 저장소에 직접 입력한다.
3. 정확한 origin·callback URI·가입 범위를 맞춘다. 소스 저장소 공개는 가입 개방을 뜻하지 않는다.
4. 실제 로그인·취소·만료·로그아웃·계정 전환과 최소 scope를 확인한다.
5. 첫 기능 수용 결과·검토 승인·운영 증거가 갖춰진 뒤 배포 단계를 진행한다.
