# 첫 기능의 공통 규칙

버전 0.4 · 구현·검수 기준 · 2026-11-10

요구 변경 CR-0003은 [다이어리 요구 정합성 기록](../changes/CR-0003-diary-requirements.md)을 따른다. 현재 제공하는 다이어리와 아직 구현하지 않은 전체 MVP의 보류·마감·시간 블록 기능을 구별한다.

## 날짜와 시간대

계정 생성 시 유효한 브라우저 IANA 시간대를 초기 제안으로 사용하고 계정에 저장한다. 읽을 수 없거나 유효하지 않으면 UTC를 사용하고 화면에 기준 시간대를 표시해 수정할 수 있게 한다. 여행·다른 기기 접속으로 기존 계정 시간대를 자동 변경하지 않는다.

실행 예정일과 마감일은 YYYY-MM-DD 달력 날짜다. 생성·수정·완료·활동 시각은 UTC 절대 시각이다. 오늘은 서버 시각을 계정 시간대로 변환한 달력 날짜다. 클라이언트 날짜만 신뢰하지 않는다. 날짜형 값을 자정 UTC로 변환하지 않는다.

시간대 변경 시 기존 날짜는 유지한다. 완료 활동의 절대 시각도 유지하고, 오늘 완료 기록의 표시 날짜는 현재 계정 시간대로 계산한다. 로그인·일자 경계·탭 재활성화 때 서버 기준 날짜를 확인하고 화면을 갱신한다. DST 하루의 범위는 현지 자정부터 다음 현지 자정까지이며 24시간으로 고정하지 않는다.

## 제목

제목은 NFC 정규화 후 앞뒤 Unicode 공백을 제거한다. 내부 공백은 유지하고 CR·LF와 NUL은 거부한다. 정규화 결과 1~200 Unicode 코드 포인트를 허용한다. 바이트 수나 UTF-16 길이로 판정하지 않는다. 서버가 최종 검증하고 클라이언트도 같은 규칙으로 안내한다. 200/201 경계와 결합 문자·이모지를 시험한다.

## 과제 상태와 완료 취소

현재 API는 open·completed·deferred·canceled를 지원하고 □ 진행 전·✓ 완료·→ 미룸·× 취소로 표시한다. 미룸은 표시 상태이며 실행일을 자동 변경하거나 해제하지 않는다. 원문 BR-07의 보류(계획 해제)는 미룸과 다른 미구현 기능이다. 완료 취소 시 실행 예정일은 유지하고 완료 시각을 해제한다. 날짜 없는 비완료 항목이 접근 불가능해지지 않도록 필요한 경우 입력함 정리 여부를 미정리로 보충한다.

open → completed는 완료 시각과 완료 활동을 원자적으로 추가한다. completed → open은 완료 취소 활동을 추가하고 이전 완료 활동을 무효화한다. 같은 상태로 다시 저장하면 새로운 완료 활동을 만들지 않는다. 재완료는 새 활동을 만든다. 현재 완료 기록에는 유효 완료만 표시한다. 성과 집계·회고 지표는 FR-07-04의 잔여 범위다.

현재 하루 계획(view=day)은 실행일별 모든 상태를 순서대로 보존한다. 완료·취소 후에도 같은 줄에 남고 하루 5개 한도에 포함한다. 이전 실행일의 open·deferred 항목은 이전 미완료 영역에서 표시하고 완료·취소는 제외한다. 기존 API view=scheduled는 완료를 제외하는 호환 조회이며 취소까지 제외하는 전체 활성 실행 목록을 구현했다는 뜻이 아니다. 완료 기록은 현재 유효한 완료의 절대 시각을 계정 시간대로 계산한다. API 0.10의 view=due는 마감이 선택 날짜이고 실행일은 다른 날/없음인 open·deferred만 구분한다. 실행일과 마감일이 같으면 day에만 표시하며 마감만 목록은 하루 5개 한도에 포함하지 않는다.

실행일·마감일은 독립적으로 지정·수정·해제하며 어느 하나의 변경으로 다른 날짜를 자동 변경하지 않는다. 마감일은 선택 사항이며 실행일보다 이른 날짜도 유효하다. 날짜 생략은 유지, null은 명시적 해제다. 과제 생성과 실제 날짜·상태·순서 변경 시 당시 계획의 before/after와 변경 후 version을 활동에 기록한다. 과거 스냅샷은 이후 변경으로 덮어쓰지 않는다. 완료 취소의 무효화 연결은 유지하며 동일 값·동일 요청 재생은 새 활동을 만들지 않는다. 기존 활동의 미보존 상세 값은 null로 표시하고 현재 값으로 추정하지 않는다.

현재 화면에는 별도 집중 과제 선택이나 상·중·하 필드가 없다. 다섯 줄의 첫 빈 줄부터 입력하고 위에 있는 항목일수록 중요하다. 마우스·터치 드래그와 키보드 대체 조작으로 dailyOrder를 변경한다. 기존 priority·kind는 호환 자료로 보존한다. 새 과제 배정과 날짜 이동은 대상 날짜의 전체 상태 개수를 잠금 안에서 확인하고 5개를 초과하면 거부한다. 기존 초과 자료는 삭제하지 않는다.

BR-07의 보류 시 실행일·시간 블록 해제, 취소의 활성 실행 제외, 완료·취소의 미래 예약 제외는 전체 MVP의 잔여 검수다. 과제의 현재 날짜·상태·순서 변경 이력은 CR-0004로 추가하되 미래 시간 블록 정리나 주간 회고 재개까지 구현한 것으로 보지 않는다. 날짜별 다이어리에 완료·취소 기호를 남기는 현재 표시와 이 정책을 혼동하지 않는다. 독립 일정·연결 시간 블록은 날짜별 30분 일정 칸과 별도 모델이다.

## 버전과 중복 요청

생성은 Idempotency-Key, 수정은 Idempotency-Key와 If-Match를 필수로 받는다. 키는 사용자·HTTP 메서드·정규 경로 범위에서 24시간 보관한다. 동일 키·동일 정규화 요청은 기존 HTTP 상태·본문·ETag를 재생한다. 만료 뒤 재전송에는 새 과제 생성 가능성이 있으므로 UI는 24시간이 지난 불확실 요청을 자동 재전송하지 않고 목록 확인을 안내한다.

다른 본문이나 If-Match로 같은 키를 재사용하면 409 IDEMPOTENCY_KEY_REUSED다. 처리 중인 키는 409 REQUEST_IN_PROGRESS와 Retry-After를 반환한다. 인증·소유권 확인 후, 저장된 동일 요청 재생을 버전 검사보다 먼저 처리해 응답 유실 후 재시도를 허용한다. 키 선점·과제·활동·재생 응답 저장은 하나의 트랜잭션에서 처리한다.

If-Match는 단일 strong ETag를 받는다. 누락은 428, 현재 버전 불일치는 412다. 실제 변경 시 버전을 1 증가시키고 변경이 없는 요청은 유지한다. 다른 사용자의 과제와 존재하지 않는 과제는 모두 404로 응답하고 소유 여부를 노출하지 않는다. 401·403·404는 요청 키를 영구 소비하지 않는다.

완료 상태와 실행일을 동시에 바꾸는 요청은 실제 값이 바뀌는 경우 버전 한 번 증가, 해당 활동을 같은 트랜잭션에서 기록한다. 버전 충돌 시 최신 항목과 현재 입력을 보여주고, 사용자가 다시 반영하면 새 If-Match와 새 키를 사용한다.

## 결정 기록과 검토

D-05의 시간대 정책, Q-001의 제목 정책, Q-002의 완료 취소 범위는 위 설계값을 제안한다. 로그인 수단과 달리 사용자 직접 확정으로 표기하지 않는다. 설계 검토에서 수정할 수 있으며 변경 시 계약·시나리오·테스트 계획을 함께 갱신한다.
