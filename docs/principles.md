# 웹 플래너 개발 원칙

버전 0.1 · 검토 초안 · 2026-11-06

## 제품과 데이터

1. 가치·목표를 설정하지 않아도 첫 기록을 저장할 수 있다.
2. 하나의 항목은 하나의 ID를 가지며 화면 간 복제하지 않는다.
3. 마감일·실행 예정일·시간 블록은 독립적이다.
4. 미완료 과제를 다음 날로 자동 복제하거나 무조건 이월하지 않는다.
5. 기록일과 생성 시각을 구분한다. 날짜형 값과 절대 시각을 구분한다.
6. 다른 사용자의 데이터 조회·수정·관계 연결을 서버에서 차단한다.
7. 서버 저장 확인 전에 저장 완료를 표시하지 않는다.
8. 중복 요청과 동시 수정으로 원본이나 이력이 손상되지 않도록 한다.

## 명세와 검증

1. 기능 명세에 목적·범위·동작·예외·수용 기준을 작성한 뒤 구현한다.
2. 구현을 막는 제품 정책은 책임자가 결정하고 기록한다.
3. 개발자는 내부 구현 선택을 수행하며 중요한 기술 선택은 결정 기록으로 남긴다.
4. 요구사항·수용 기준·작업·PR·테스트·릴리스의 연결을 유지한다.
5. 구현 완료와 검수 통과, 배포 완료를 별도 관리한다.
6. 초기 성능 수치는 검토 목표이며 대규모 운영 SLA로 간주하지 않는다.
7. AI 작성 결과도 동일한 리뷰와 검증을 거친다. AI가 요구 승인이나 배포 수용을 대신하지 않는다.

## 자료와 접근

GitHub에는 코드, 기술 명세, 테스트, 합성 테스트 데이터, CI 정의를 저장한다. Google Drive에는 요구사항 관리표, 디자인·검토 자료와 승인된 증적을 보관한다. 비밀값은 별도 비밀 관리 수단에 두고, 사용자 일기나 운영 데이터는 일반 개발 자료와 분리한다. 두 계정 간 공유 권한을 자동 확대하지 않는다.
