# 명세 기반 개발 진행 기준

버전 0.1 · 검토 초안 · 2026-11-06

## 단계와 통과 조건

| 단계 | 산출물 | 통과 조건 |
|---|---|---|
| 요구 분석 | 요구 ID, 범위, 우선순위, 결정 목록 | 목적과 MVP 경계가 명확함 |
| 기능 명세 | spec.md, 수용 시나리오 | 구현을 막는 미결정 사항 해소 |
| 설계 | UX 흐름, 데이터 모델, API 계약, 기술 결정 | 공통 규칙과 수용 기준 충족 가능 |
| 작업 분해 | tasks.md, 테스트 매핑 | 각 작업에 목적·검증·의존성 존재 |
| 구현 | 코드, 마이그레이션, 자동 테스트 | 리뷰와 관련 자동 검사 통과 |
| 검수 | 수용 기준별 결과·증적 | 필수 동작과 적용 품질 조건 충족 |
| 배포 | 릴리스 구성, 복구 절차, 운영 확인 | 지정 책임자의 출시 판단 완료 |
| 운영 개선 | 오류·사용 피드백·변경 요청 | 요구 목록과 명세에 환류 |

## 변경 절차

요구 변경은 사유와 영향을 기록하고, 명세·설계·테스트·작업을 함께 수정한다. 구현이 명세를 위반한 경우에는 결함으로 처리한다. 긴급 장애는 최소 수정·검증·복구를 우선하되 누락된 기록을 후속 보완한다.

승인된 명세 변경은 PR로 검토한다. 배포 기록에는 코드 커밋과 명세 버전을 함께 고정한다. 구글 시트의 관리 상태는 연결된 증적을 확인한 뒤 갱신하며, 명세 복사본을 별도 기준으로 운영하지 않는다.

## 최소 PR 정보

- 관련 요구사항 ID와 기능 명세.
- 바뀌는 동작과 변경 사유.
- 수행한 검증과 증적.
- 데이터 변경·호환성·복구 영향.
- 미해결 사항과 필요한 결정.

## 적용 순서

공통 규칙 → 계정과 빠른 입력 → 과제와 오늘 화면 → 일정과 재계획 → 목표와 컬렉션 → 주간 계획과 회고 → 검색과 데이터 관리 → 통합 베타 순서로 진행한다. 접근 제어와 저장 신뢰성은 각 단계에 포함한다.
