# CR-0004 마감일 편집과 계획 변경 이력

기능 명세 0.11 · API 0.10.0 · 2026-11-10

사용자가 다음 구현 대상으로 승인한 마감일 편집, 실행일과 마감일의 구분, 계획 변경 이력을 기존 다이어리에 추가한다. 요구 ID를 새로 만들거나 원문을 완화하지 않고 기존 요구의 구현 범위를 확장한다. 요구 관리표의 유효 분모 92개는 그대로다. 구현·검수 상태는 실행 증거 확인 뒤 갱신한다.

| 대상 | 이번 범위 | 별도로 남기는 범위 |
|---|---|---|
| FR-04-02 | 실행일 다섯 줄과 마감만 선택 날짜인 목록을 구별하고 중복 표시를 방지 | 독립 주간·월간 일정 전체 |
| FR-05-01 | 제목·상태·실행일에 마감일 입력·수정·해제를 추가 | 본문·예상 시간·목표·컬렉션·태그. 전체 요구 완료로 처리하지 않음 |
| FR-05-02 | 실행일과 마감일의 양방향 독립성, 기존 날짜 보존 회귀 | 없음. 기존 통과 근거를 유지하면서 새 쓰기 경로 재검증 |
| FR-05-03 | 미래 계획 과제의 현재 완료일 기록과 원래 계획 스냅샷을 보존·조회 | 성과 집계와 주간 회고 전체 |
| FR-12-02 | 실행일 이동·해제·재배정에도 같은 원본 ID와 날짜 변경 전후 이력을 유지 | 주간 회고 기본 흐름과 일괄 재계획 |
| FR-12-03 | 이번 구현에 포함하지 않음 | 회고 중단 후 답변·검토 위치 보존은 미구현 유지 |

이전 진행 기록에서 계획 변경 이력에 연결한 FR-12-03은 추적 오류다. 원문 FR-12-03은 `회고 중단과 재개`이고, 정확한 날짜 변경 이력 요구는 FR-12-02 `재계획 원본과 이력`이다. 이 정정으로 회고 기능을 완료 처리하거나 범위를 삭제하지 않는다.

## 설계 영향

dueDate는 기존 tasks 필드를 쓰며 신규 생성·수정 계약만 확장한다. 마감만 목록은 실행일과 다르거나 날짜가 없는 open/deferred 항목만 조회하므로 다섯 줄 한도와 별개다. 완료·취소 항목은 해당 실행일의 기존 다이어리 줄에 유지한다.

task_activities에 nullable JSONB details를 추가한다. 새 활동에는 날짜·상태·순서의 before/after와 변경 후 version을 기록하고 기존 활동은 null을 보존한다. API는 이력을 소유자별·과제별로 페이지 조회하며 변경 API는 제공하지 않는다. 기존 활동의 완료 취소 연결과 같은 요청 재생을 유지한다. 과제·활동·재생 응답의 원자성, 날짜별 한도, 오래된 If-Match, 다른 계정·변조 커서를 고위험 검증 대상으로 둔다.

기존 9개 테이블을 유지하고 마이그레이션은 7개, API 작업은 이력 GET 추가로 12개다. 제품 저장소와 체험 저장소의 자료는 분리한다. 실제 Google 로그인은 중지 상태를 유지하며 운영 배포나 사용자 수용 승인을 이번 구현 검수로 대체하지 않는다.

## 통과 조건

V-15의 계약·이전 자료 보존·실제 PostgreSQL 원자성 및 PC/모바일 브라우저 검증을 통과한 뒤 다음 구현으로 진행한다. 기존 날짜별 다섯 줄·반응형·일정·자유글·충돌 복구 회귀도 포함한다. [검증 기록](../verification/deadline-history.md)에 실행 환경·명령·결과와 남은 외부 검증을 구분한다.
