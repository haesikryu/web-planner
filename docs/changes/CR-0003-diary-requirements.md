# CR-0003 다이어리 요구사항 정합성

요구 기준 v0.2 · 기능 명세 0.10 · 2026-11-10

현재 위치는 SDLC 6단계 검수다. 사용자가 명시적으로 요청한 다이어리 변경이 구현·기능 명세에는 있지만 최초 요구 관리표에는 빠져 있던 문제를 정리한다. 앞선 CR-0002는 기존 86개 요구를 그대로 평가하여 완료·통과 16개(18.6%)로 기록했다. 이번 변경은 최신 요청을 추적하는 명세 변경이며 실제 Google 로그인·운영 배포·사용자 인수승인을 뜻하지 않는다.

## 변경 근거

사용자는 별도 입력 폼 대신 다섯 줄을 순서대로 입력하고, 사각형을 눌러 완료·미룸을 선택하며, 줄을 끌어 놓아 중요도를 정하도록 요청했다. 유형과 상·중·하 선택은 제거한다. 왼쪽은 할 일과 06시~24시의 30분 일정, 오른쪽은 자유 기록으로 구성하고 달력에서 날짜를 선택한다. PC와 가로 태블릿은 이틀, 세로 태블릿과 휴대폰은 하루를 표시하며 화면 높이에 맞춘다.

이 요청은 별도 집중 선택과 3개 권장 정책을 대체한다. 메모·사건·독립 일정, 과제 상세 필드, 목표·컬렉션·회고·검색·데이터 관리까지 제거하는 근거는 아니다. 자유글 요청도 기존 저장 실패·이탈 경고 기준을 완화하는 근거가 아니다.

## 집계와 추적

등록 요구는 86+7=93개이고 폐기 1개를 제외한 유효 요구는 92개다. 요구 승인·구현 완료는 유효 요구 수를, 검수 통과는 유효 요구에 연결된 검수기준 수(현재 92개)를 분모로 사용한다. 하나의 요구에 여러 검수기준을 추가하면 두 분모는 달라질 수 있다. 검수는 요구 ID로 요구상태를 찾아 폐기 여부를 결정하며 행 순서에 의존하지 않는다. 폐기 행과 검수 행은 삭제하지 않는다. 기존 86개 기준의 16/86은 CR-0002에 보존하고 다른 기준의 수치를 직접 공수 진척으로 비교하지 않는다.

상태를 변경한 항목에는 판정 사유·실제 시험 범위·소스와 시험 근거·검토일을 기록한다. 구현과 검수의 상태를 요구 승인이나 배포 상태에 복사하지 않는다. API 0.9.0, 9개 테이블, 6개 마이그레이션은 유지하며 사용자 데이터 변환은 없다.

## 이번 검증 보완과 이후 작업

FR-05-02는 non-null 마감일이 있는 기존 과제의 실행일 변경·해제·재배정·실패·재생을 직접 검수한다. 마감일 편집 기능은 포함하지 않는다. NFR-02는 실제 Tab/Shift+Tab/Enter/Space/방향키만 사용하는 브라우저 흐름으로 입력 오류·순서·상태·달력·일정·글 저장과 재조회를 검수한다. 프로그램으로 focus/click/fill하여 키보드 탐색을 생략하지 않는다.

실행 결과는 [검증 기록](../verification/requirements-alignment.md)에 고정한다. 고위험 검사 통과 후 적용 순서에 따라 과제 마감일 편집·실행일/마감일 구분과 계획 이력, 그 다음 일정·재계획을 다음 구현 단위로 구체화한다. 실제 공급자 로그인은 사용자 요청으로 중지한 상태를 유지하며 운영 준비는 별도다.
